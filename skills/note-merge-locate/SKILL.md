你在做「融入当前笔记」的**第一步：决定放哪儿**。

笔记有大几千到几万字，让模型一次性重写整篇会撞输出上限（截断的结果看起来还像是完成的），
所以这一版分两步：**这一步只做定位**，输出极小；下一步只改写你选中的那一节。
因此：**这一步一行正文都不要写。**

你会拿到：
- **笔记大纲**：编号 + 小节标题 + 该节字数 + 子标题 + 开头一句（**不是全文**，你也不需要全文）；
- **新内容**：要融进去的那段知识；
- **用户当时问的问题**：只用来判断主题归属，不必写进笔记。

## 输出：严格 JSON，不要任何其它文字、不要代码围栏

```
{"action":"merge","index":3,"heading":"","reason":"一句话理由"}
```

| action | 含义 | index | heading |
| --- | --- | --- | --- |
| `merge` | 并进第 N 节 | 必填，大纲里的编号 | 留空 |
| `append` | 现有小节都装不下，在第 N 节**之后**新增一节 | 必填；`0` 表示放在整篇末尾（笔记没有可用分节时） | 给一个自拟标题 |
| `covered` | 这条内容笔记里已经有了，不必融入 | 留空 | 留空 |

## 怎么选

1. **语义优先**：标题语义相同、或明显属于同一主题 → `merge` 那一节。
2. 新内容是某一节的展开 / 补充（同一个术语、同一个 API、同一个场景）→ 就是那一节。
3. 大纲里的字数是给你判断"这一节是不是已经很大"的参考，**但不要因为某节大就避开它** ——
   下一步会自己决定是整节重写还是只往里加一个子小节。定位只看主题，不看大小。
4. **不要因为"它在最后"就选它**。只有确实无法归类时才 `append` 到末尾，并给它一个概括性标题
   （例如「其他」）；能归到某一节附近就插在那一节之后，用它的编号。
5. 别选「其他 / 杂项」这类兜底节，除非确实只有它。
6. 新内容与笔记已有内容**说的是同一件事**（不是"相关"，是"已经讲过"）→ `covered`，并在
   `reason` 里说明是在哪一节。宁可不融入，也不要在笔记里留下两份近似内容。

## 边界

- 大纲里没有编号小节（笔记没有可用标题）→ 输出 `{"action":"append","index":0,"heading":"补充","reason":"笔记没有分节标题"}`。
- 拿不准就选**语义最近**的那一节，不要写 `append` 蒙一个位置。
- `reason` 一句话即可（不超过 30 字），它是给用户看的解释，不要复述规则。
