# markdown-polish · 参考材料

> 本文件是技能 `skills/markdown-polish/SKILL.md` 的**配套参考**，不会被送进模型 ——
> 送进模型的只有 SKILL.md 的正文（frontmatter 之外的全部内容）。
> 这里保留设计论证，改提示词前先读第 3 节：**不要与另一套规则混用**。

---

## 2. 为什么这样写（消歧手法）

「必要时可扩写或缩写」这句话本身是有歧义的——什么叫"必要"？不同人、不同次调用会得到完全不同的结果。
本提示词用四种手法把它变成**可判定、可复现**的规则：

| 手法 | 具体做法 |
| --- | --- |
| 触发条件化 | 把"必要时"拆成可枚举的条件（重复、填充词、冗余修饰 / 指代不明、缺前提、缺界定），逐条列出 |
| 以"信息点"替代"字数" | 缩写标准是**信息点不减少**，而不是字数达标——避免模型为凑字数注水，也避免它拿字数当免罪符 |
| 双边界夹逼 | 下界 60%（不许大砍）、上界 150%（不许灌水），中间留出合理的改写空间 |
| 冲突时优先级明确 | 明确规定"任何规则与保持原义冲突，以保持原义为准"，避免规则打架时模型自由发挥 |

另外三处刻意留白：

- **不注入术语表之外的知识**：明确禁止"引入原文没有的技术事实"，防止润色变成"顺手补充内容"而引入错误。
- **不确定时不动**：这是纠错场景下最安全的默认值，宁可少改。
- **原文已合规就原样返回**：明确禁止"为了看起来改过而改写"，避免无意义抖动。

## 3. 与内置默认提示词的差异

| 项 | 内置默认（`DEFAULT_POLISH_PROMPT`） | 本版 |
| --- | --- | --- |
| 缩写 | **禁止**："严禁压缩与删减""字数不得少于原文" | **允许**，但限定触发条件 + 信息点不减少 + 长度下界 60% |
| 扩写 | 未提及 | **允许**，但限定触发条件 + 不得引入新事实 + 长度上界 150% |
| 术语表 | 只举例（maven→Maven 等 4 个） | 22 条固定映射 |
| 冲突处理 | 未规定 | 明确规定"以保持原义为准" |
| 分段场景 | 未提及 | 明确片段处理规则（与工程分块策略对齐） |

> 结论：默认版是「只准改语言、不准动篇幅」；本版是「篇幅可变，但信息点与事实不可变」。
> 两者都自洽，按需要选一个——**不要混用**，否则模型会同时收到"不许删"和"可以删"两条指令。

## 4. 与工程实现的关系（必须一起看）

实现位于 `backend/src/main/java/org/dyh/learnhub/ai/AgentService.java` 的 `polish()`：

| 机制 | 取值 | 与本提示词的关系 |
| --- | --- | --- |
| 分块阈值 | `POLISH_CHUNK_CHARS = 4000` | 超过 4000 字会切片，每片独立调用；故提示词第八节规定片段行为 |
| 单轮预算 | `ROUND_BUDGET_MS = 270000`（270s）、`MIN_STEP_BUDGET_MS = 30000` | 段数多时可能提前失败并提示"分段选中后再处理" |
| 长度守卫 | `POLISH_MIN_RATIO` | 输出短于原文该比例 → 判定为"疑似缩水"并**静默回退原文** |

**这里原有一个冲突**：守卫原值为 `0.75`，而本版提示词允许缩写到 60%。若模型按提示词缩写到 65%，
守卫会判定"缩水"，把结果丢掉并返回原文——用户看到的是"处理完成但内容没变"，
既无明显报错，也无从判断原因。

因此配套调整：**`POLISH_MIN_RATIO` 由 0.75 下调为 0.6**，与提示词的长度下界对齐。
守卫仍然有效（它防的是模型输出被截断这类真实故障），只是不再把"合规的缩写"误判成故障。

> 如果你希望更自由地缩写，可以在设置里改提示词的长度下界，但**必须同步调低这个常量**，
> 否则改动不会生效。二者是一对，不能只改一边。
## 6. 自检清单（改完提示词后过一遍）

- [ ] 缩写是否有明确的触发条件，而不是"必要时"
- [ ] 是否用"信息点"而非"字数"作为缩写标准
- [ ] 是否给了长度上下界，且与 `POLISH_MIN_RATIO` 不冲突
- [ ] 是否规定"规则冲突时以保持原义为准"
- [ ] 是否禁止引入原文没有的技术事实
- [ ] 是否说明了分块（片段）场景下的行为
- [ ] 是否要求"只输出正文、不要前后缀与整篇代码围栏"
- [ ] 与内置默认提示词是否**只启用了一个**（不要混用两套矛盾规则）
