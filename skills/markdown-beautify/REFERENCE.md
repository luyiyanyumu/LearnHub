# markdown-beautify · 参考材料

> 本文件是技能 `skills/markdown-beautify/SKILL.md` 的**配套参考**，不会被送进模型 ——
> 送进模型的只有 SKILL.md 的正文（即原文档第 6 节的精简版提示词）。
> 下面保留了完整排版规范与能力清单：SKILL.md 是"给模型看的最小充分说明"，
> 本文件是"给人看的完整规格"，多了往返安全性、黑名单成因与完整样例。

---

## 0. 一句话总则

**结构靠标题层级，重点靠加粗与一种语义色，代码靠围栏，其余一律不用。**
界面本身是「安静的高级感」——笔记正文跟着这个基调：宁可少一个装饰，不多一个字号。

## 1. 能力清单（本工程真实支持）

### 1.1 白名单：可以放心用

| 类别 | 写法 | 说明 |
| --- | --- | --- |
| 标题 | `#` `##` `###` | 右侧「大纲」自动收录这三档；`####` 及以下不显示在大纲 |
| 加粗 / 斜体 | `**粗**` `*斜*` | 首选强调手段 |
| 删除线 | `~~文字~~` | 反推时自动归一为双波浪线 |
| 行内代码 | `` `code` `` | 命令、变量名、字段名 |
| 代码块 | ` ```java ` … ` ``` ` | 带语言名才高亮 |
| 表格 | `| a | b |` + `| --- | --- |` | 支持 `:---` / `:---:` / `---:` 对齐 |
| 任务列表 | `- [ ]` / `- [x]` | 渲染成勾选框 |
| 引用 | `>` | 用于原文摘录、官方文档原话 |
| 分割线 | `---` | 用于大段落切换，克制使用 |
| 链接 | `[文字](https://…)` | 裸 URL 会自动识别 |
| 图片 | `![说明](路径或URL)` | 也可上传到「资料库」后引用 |
| 提示块 | `:::tip` / `:::warning` / `:::success` … | 见 2.7 语义映射 |
| 折叠块 | `<details>` + `<summary>` | 见 2.8，**内部 Markdown 前后必须留空行** |
| 文字颜色 | `<font style="color: rgb(245, 34, 45)">文字</font>` | 见 2.4 语义色板 |
| 行内高亮 | `<mark>文字</mark>` | 双主题安全，**优先用它** |
| 文字底色 | `<font style="background-color: #fdf6d8; color: #262626">文字</font>` | 浅底必须同时写死文字色，见 2.4 |
| 字号 | `<font style="font-size: 12px">文字</font>` | 正文禁用，仅标注类文本 |
| 下划线 / 上标 / 下标 | `<u>` `<sup>` `<sub>` | 上标下限用于单位、脚注 |
| 段落对齐 | `<p style="text-align: center">文字</p>` | 仅用于封面标题、图注 |
| 保留标签 | `<kbd>` `<abbr>` `<small>` `<big>` `<span>` | 会被原样保留，不乱用即可 |

### 1.2 白名单：数学公式（LaTeX）

| 写法 | 效果 |
| --- | --- |
| `$E=mc^2$` | 行内公式，用 KaTeX 排版 |
| `$$ x = \frac{-b \pm \sqrt{b^2-4ac}}{2a} $$` | 独立成行的公式（可跨行） |
| `\(a^2+b^2=c^2\)` / `\[ … \]` | LaTeX 原生定界符，等价于上面两种 |

- 笔记（块编辑器与预览）、速查卡、智能体回答三处都渲染；编辑时公式存的是**LaTeX 源码**，
  在块编辑器里双击公式即可改，或去「源码对照」直接改 `$…$` / `$$…$$`。
- 别用图片代替公式，也别用 Unicode 上下标 / `√` 硬凑：那样渲染不出数学排版，也无法再编辑。
- `$5 与 $6`（价格）、`$ 两边有空格 $` 不会被当成公式；代码块与行内代码里的 `$` 原样保留。

### 1.3 黑名单：不要用（会被破坏或显示不出效果）

| 禁用 | 原因 |
| --- | --- |
| ` ```mermaid ` | **本工程未接 mermaid**。预览里会残留原样代码，且反推同步会直接报「无法安全反推」，编辑被拦住 |
| 嵌套 `:::tip` 里再套 `:::` | 容器不支持嵌套，遇到第一个收尾 `:::` 就闭合，结构会错位 |
| 只写开头不写收尾的 `:::` | 找不到收尾就按普通文本渲染，页面上会多出 `:::tip` 字样 |
| 裸 `<div>` / `<div style>` / `<iframe>` / `<section>` | 反推回 Markdown 时无法表达，会被压平成纯文本，样式全丢 |
| 手改标题里的 `id` / `class` | 反推时会丢，白费功夫 |
| 拖动表格列宽 | 有显式尺寸的表格反推时会退化成一大段内联 `<table>` HTML，无法再当管道表编辑 |
| 用字号表达层级 | 层级是标题的职责；正文里混字号会让整篇失去节奏 |
| 深色文字色单独使用 | 深色主题下会糊掉，见 2.4 |

## 2. 排版规范

### 2.1 文档骨架与标题

- **一篇笔记只用一个 `#`**（笔记正文标题其实由页面顶部的「标题」字段承担，正文里 `#` 可省略；若要用，只用在开头一次）。
- 结构层次固定为 `##` → `###`，**不要跳级**（`##` 下面直接 `####`）。
- `####` 及以下不会出现在大纲里，长文尽量不用。
- 标题文字保持干净：**不要**在标题里塞行内代码、删除线、上下标。
- 标题可以带颜色，但**全篇只用一种**（推荐 `#1677ff` 蓝），不要每个标题一个色。

```md
## 一、Java 核心基础
### （一）Java 基础
#### 1. Java 简介   ← 这档不会进大纲，慎用
```

### 2.2 目录

- **主目录是自动的**：右侧「大纲」面板实时从 `#`/`##`/`###` 生成，并在滚动时高亮当前小节。
  所以**不要手写一份大目录**，那是重复劳动，还会随内容变化失同步。
- 什么时候才手写目录：长文（> 5000 字）且需要**明确控制目录顺序/措辞**时，用链接列表。
  锚点现在**在预览和导出 HTML 里都能跳**（`mdAnchor` 插件同时挂在两条渲染链上）。

**锚点 id 规则（写目录时必须按这个拼）**

| 步骤 | 规则 | 例 |
| --- | --- | --- |
| 1 | 去掉标题里的行内 HTML 标签与强调符号 `*` `` ` `` `~` | `**重点**` → `重点` |
| 2 | 整体转小写 | `Java` → `java` |
| 3 | 只保留 中文 / 字母 / 数字 / 空格 / 下划线 / 连字符，标点全部丢弃 | `一、Java 核心基础` → `一Java 核心基础` |
| 4 | 空白与下划线合并为单个 `-`，去掉首尾 `-` | `1. Java 简介` → `1-java-简介` |
| 5 | 同名标题依次追加 `-1`、`-2`；空标题用 `section` | 第二个 `## 小结` → `#小结-1` |

```md
## 目录
- [一、Java 核心基础](#一java-核心基础)
- [二、数据库核心技术](#二数据库核心技术)
```

> 规律记一条就够：**中文保留、英文小写、标点删掉、空格变短横线**。
> 例：`### （一）Java 基础` → `#一java-基础`（中文括号被丢弃）。
>
> 说明：导出 HTML 的源码里 `href` 会写成百分号编码（如 `#%E4%B8%80java-…`），而标题的 `id`
> 保持原始中文。这是浏览器既定行为——点击时先解码 fragment 再匹配 `id`，能正常跳转；
> **不要手动改写成编码形式**，按上表写原始中文即可。

### 2.3 加粗与强调的分工

| 手段 | 用来表达 | 不要用来表达 |
| --- | --- | --- |
| `**加粗**` | 定义句的关键术语、结论、必须记住的一句话 | 整段整段地加粗 |
| `*斜体*` | 英文术语首次出现、书名/产品名 | 中文句子 |
| `` `行内代码` `` | 命令、类名、方法名、参数、字段名 | 普通名词 |
| `~~删除线~~` | 纠错（写错了但保留痕迹）、过时结论 | 表示否定 |

**密度上限**：一段里最多加粗一处。加粗太多等于没有加粗。

### 2.4 重点词语的颜色突出

**语义色板**（同一语义全篇固定用同一个色，不要随手换）：

| 语义 | 色值 | 典型场景 |
| --- | --- | --- |
| 风险 / 错误 / 禁止 | `#f5222d` | 坑、异常、不要这么写 |
| 注意 / 警告 | `#fa8c16` | 需谨慎、平台差异、性能代价 |
| 正确 / 推荐 | `#52c41a` | 最佳实践、官方推荐写法 |
| 信息 / 定义 / API | `#1677ff` | 概念定义、接口名、配置项 |
| 概念 / 原理 | `#722ed1` | 设计思想、底层机制 |
| 补充 / 历史 | `#8c6b4f` | 版本沿革、题外话 |

**三条硬规矩**：

1. **一篇最多 3 种颜色**。第 4 种出现时，说明该改写结构而不是继续上色。
2. **不要给整段上色**。只标一个词、一个短语，最多半句。
3. **深色主题安全**：
   - 单用深色文字（`#262626` / `#595959` / `#8c8c8c`）在深色主题下会糊掉 → **要么不用，要么配浅底**。
   - 加浅色底时**必须把文字色一起写死**，否则深色主题下变成"浅底 + 浅字"：

```md
<font style="color: rgb(245, 34, 45)">不要用 == 比较对象</font>
<font style="background-color: #fdf6d8; color: #262626">局部变量</font>
<mark>最高优先级</mark>
```

> 行内高亮**首选 `<mark>`**：它用浏览器原生配色，深浅两套主题都自动可读。

### 2.5 字号使用规范

- **正文一律不设字号**（跟随界面 14px 基准）。用字号做层级是最常见的"廉价感"来源。
- 确需标注时，只准用 **3 档**：`12px`（脚注、图注、补充说明）、`14px`（与正文同级，用于同行内的小字说明）、`16px`（封面/引言）。
- `18px` 及以上的档位留给标题体系与文档封面，正文里出现即为越界。

```md
<font style="font-size: 12px">注：该方法在 JDK 9 之后被标记为 deprecated。</font>
```

### 2.6 代码

- 行内代码用单反引号；**只要有换行就必须用围栏代码块**。
- 围栏必须写语言名，否则不高亮：`java` `python` `js` `ts` `vue` `sql` `bash` `json` `yaml` `xml` `html` `css` `go` `rust` `sh` `properties` `diff`。
- **代码块里禁止放颜色标签 / 加粗 / 字号**——代码要保持可以被复制粘贴直接运行。
- 代码里含三连反引号时，外层围栏要更长：

````md
````md
```java
System.out.println("嵌套示例");
```
````
````

- 超长代码（> 40 行）用折叠块包住，只留关键几行在正文：

```md
<details>
<summary>完整示例代码（点击展开）</summary>

```java
// 完整代码…
```

</details>
```

- 输出结果、报错信息也当代码块处理（`text` 或 `bash`），不要用普通段落加引号。

### 2.7 提示块 `:::`

支持的名称（其余名称会渲染成中性灰）：`success` `tip` `info` `note` `warning` `attention` `danger` `error`

| 名称 | 语义 | 颜色 |
| --- | --- | --- |
| `success` | 结论 / 已验证有效 | 绿 |
| `tip` | 小技巧、快捷做法 | 青 |
| `info` / `note` | 补充说明、前置条件 | 蓝 |
| `warning` / `attention` | 小心、版本差异、性能代价 | 橙 |
| `danger` / `error` | 会导致故障的写法 | 红 |

```md
:::warning
JDK 8 与 JDK 17 的 `Files.readString` 行为不同，迁移时注意。
:::
```

- 一个提示块只讲一件事；不要在里面对付长段落。
- 提示块内部可以放列表、代码块、标题。
- **不要嵌套**提示块；**收尾 `:::` 不能漏**。

### 2.8 折叠块

用于"可选阅读"的内容：长代码、完整日志、延伸阅读、推导过程。

```md
<details>
<summary>为什么这里要加锁（点击展开）</summary>

正文内容按正常 Markdown 写，**前后各留一个空行**才会被解析。

</details>
```

### 2.9 表格

- 只用于**真正多列对比**的信息（参数、方案取舍、版本差异）。两列且内容是句子时，改用列表。
- 列数控制在 4–6 列；表头用短语，不要句子。
- 首列放"被比较的对象"，其余列放属性。
- 单元格里可以用行内代码与加粗，**不要放代码块、列表、多行内容**。
- 对齐用 `:---:`（数值居中）或有意义地使用左对齐；**不要拖动列宽**（见黑名单）。

```md
| 特性 | JDK 8 | JDK 17 |
| --- | :---: | :---: |
| `var` 局部变量 | ✗ | ✓ |
| record | ✗ | ✓ |
```

### 2.10 列表与任务列表

- 无序列表用 `-`（统一，不要混用 `*`）。
- 有序列表只在**步骤有严格先后**时用（操作步骤、排查顺序）。
- 列表项尽量一行说完；要展开就拆成小节。
- 待办类内容用任务列表，一眼看出进度：

```md
- [x] 掌握 `synchronized` 与 `ReentrantLock` 的区别
- [ ] 补充 AQS 的源码阅读笔记
```

### 2.11 引用与分割线

- `>` 用于**引用外部原话**（官方文档、书籍、他人的结论），并标注出处。
- 不要用 `>` 代替提示块——语义不同：引用是"别人的话"，提示块是"我的提醒"。
- `---` 只用于大章节之间的切换，一篇不超过 3 处。

### 2.12 图片与链接

- 图片必须写**有意义的说明文字**（`![线程状态转换图](…)`），空说明会影响可读性。
- 图片下面可以配一行小字图注：
  ```md
  <font style="font-size: 12px">图 1：线程六状态与转换条件</font>
  ```
- 外链写清楚来源平台，便于日后回溯：`[ArrayList 源码分析 · 美团技术团队](https://…)`。

## 3. 反推（往返）安全：哪些写法会被"洗掉"

本工程的编辑页支持**直接在右侧预览里改格式**，保存时会把所见内容反推回 Markdown（Turndown + 自定义规则）。
反推会做几件归一化的事，知道它们就不会踩坑：

| 反推行为 | 影响 |
| --- | --- |
| 行尾空格被清除 | 硬换行 `两个空格 + 换行` 会变成普通换行（因渲染器 `breaks: true`，显示效果不变） |
| 连续 3 个以上空行压成 1 个空行 | 不要靠空行做视觉间距 |
| 列表项多余缩进被压缩 | `-   项目` 会变成 `- 项目` |
| `&nbsp;` → 普通空格 | 不要用 `&nbsp;` 做对齐 |
| 带尺寸的表格转成内联 HTML | 这就是"别拖列宽"的原因 |
| 提示块还原成 `:::名称 … :::` | 名称取自 CSS 类，所以只能用 2.7 那 8 个名称 |
| 代码块围栏自动加长 | 代码里含反引号不会破坏结构，放心写 |
| Mermaid 图表**拒绝同步** | 会提示「无法安全反推」，保存被拦住（这是保护，不是 bug） |

**一句话结论**：只用第 1.1 节白名单里的写法，右栏编辑与源码栏可以任意来回改，永远不坏。

## 4. 完整样例（照着这个风格写）

````md
## 一、Java 核心基础

### （一）Java 基础

#### 1. Java 简介

Java 是一门<font style="color: rgb(22, 119, 255)">面向对象</font>、跨平台、编译型 + 解释型的高级编程语言。

:::info
**核心概念区分**
- **JVM**（Java 虚拟机）：运行字节码的核心，是跨平台的基石
- **JRE**（Java 运行环境）：JVM + 核心类库，能运行程序
- **JDK**（Java 开发工具包）：JRE + 编译器 `javac` 等开发工具
:::

#### 2. Java 的三大特性

1. **跨平台**：一次编写，到处运行。`.java` 编译成 `.class`，由各平台 JVM 执行
2. **面向对象**：封装、继承、多态
3. **自动内存管理**：GC 负责回收，<font style="color: rgb(250, 140, 22)">但仍可能内存泄漏</font>

:::warning
`System.gc()` 只是<font style="background-color: #fdf6d8; color: #262626">建议</font>，JVM 可以不执行。
:::

#### 3. 一段最小示例

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
    }
}
```

<details>
<summary>为什么 main 方法必须是 static（点击展开）</summary>

JVM 在启动时还没有创建任何对象，只能通过类直接调用，因此 `main` 必须是静态的。

</details>

| 版本 | 引入方式 | 是否需显式编译 |
| --- | :---: | :---: |
| JDK 8 | 常规编译 | 是 |
| JDK 11 | `java Hello.java` 单文件 | 否 |

- [x] 理解 JVM / JRE / JDK 的关系
- [ ] 补充 JIT 编译的笔记
````

## 运行时接线（改为技能之后）

| 机制 | 现在的来源 |
| --- | --- |
| 提示词正文 | `skills/markdown-beautify/SKILL.md` 的正文，**每次请求实时读盘** |
| 长度下界 | frontmatter `min_ratio: 0.6`，由 `AgentService` 的长度守卫读取 |
| 分块阈值 / 预算 | 同 markdown-polish：`POLISH_CHUNK_CHARS = 4000`、`ROUND_BUDGET_MS = 270s` |
| 原第 6 节「精简版提示词」 | 已上移为 SKILL.md 的正文，此处不再重复 |
