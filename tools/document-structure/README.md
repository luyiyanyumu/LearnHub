# 高精度本地文档扫描侧车

本目录实现 PP-StructureV3 的单页 PNG 服务。应用接入、分批扫描及资料更新行为见 [本地文档扫描与 OCR](../../docs/document-ocr.md)。运行时不下载模型，不接受文档路径或 URL，不挂载用户资料目录。

## 模型与运行配置

| 阶段 | 固定模型 |
| --- | --- |
| 版面检测 | `PP-DocLayout_plus-L` |
| 文字检测 | `PP-OCRv5_server_det` |
| 文字识别 | `PP-OCRv5_server_rec` |
| 公式候选 | `PP-FormulaNet_plus-L` |
| 规则表格 | `SLANet_plus` |

`models.py` 固定官方下载地址及每个模型文件的 SHA-256；构建时下载并校验，单个压缩包上限为 1 GiB。CPU 依赖固定为 PaddleOCR 3.7.0、PaddleX 3.7.2 和 PaddlePaddle 3.3.0。GPU 镜像基于相同源码和模型，将推理包替换为官方 CUDA 12.6 源提供的 `paddlepaddle-gpu==3.3.0`。

引擎标识保持 `pp-structurev3`。健康响应同时返回 `profile=high-quality-v2`、`version=3.7.0-hq2`、模型名单及实际 `device`；识别响应也包含该 profile。只有模型已初始化成功才返回就绪。工作进程异常退出后按 5 至 60 秒退避重建，不自动重放失败请求。

文字检测输入长边最多 1920 像素，文字识别批量为 4，公式识别批量为 1；最终坐标对应传入的原始 PNG。单页推理预算为 240 秒。表格结构校验和公式待核对规则仍然生效，高精度模型不代表所有输出都可直接作为可靠正文。

版面标记为 `image`、`chart` 或 `figure` 的区域保留为有坐标的 `figure` 块，由应用裁取原图；区域没有 OCR 文字时也保留。图中识别出的文字作为独立、有坐标的正文证据输出一次，不复制模型生成的图片路径、Markdown 或描述。此输出修复使用新的 v2 profile，旧 v1 扫描候选不能作为 v2 继续累积；模型权重和推理参数保持相同。

CPU Compose 覆盖文件配置 4 个 CPU 配额、6 GiB 内存上限及 4 个推理线程。**这些是资源上限，不是 CPU 模式已通过完整页面验收的承诺。** 未限制文字检测尺寸的早期高精度 CPU 候选曾在 6 GiB 上限下内存不足；采用当前 1920 像素限制的 CPU 候选尚未完成完整页面验收，不能把 GPU 结果视作 CPU 的容量或性能依据。

可选的 `deploy/docker-compose.document-structure-gpu.yml` 应叠加在基础部署和结构化扫描覆盖文件之后，要求 NVIDIA 容器运行环境。先构建当前源码的 CPU 镜像，再构建基于它的 GPU 镜像；GPU 层仅替换推理运行时。运行设备由 `LEARNHUB_STRUCTURE_DEVICE` 指定，仅允许 `cpu` 或 `gpu:0`。两种方式均保留内部网络、只读根文件系统、非 root 用户和无资料目录挂载的约束。

## 合成样本验证记录

2026-11-12 的 GPU 验证使用两张完全合成的中英文页面，不含用户资料。以下首轮记录对应 v1 profile 的直接推理调用。容器限制为 4 个 CPU 配额和 6 GiB 主机内存，使用 NVIDIA GPU，根文件系统只读且无网络。模型初始化耗时 32.598 秒，两页依次完成，进程正常退出；记录到的进程最大常驻内存为 2508.8 MiB。该内存值不包含 GPU 显存，也不等于整个容器峰值内存。

| 合成页面 | 推理耗时 | 归一化文本编辑距离 | 匹配文字区域 |
| --- | --- | --- | --- |
| 单栏中英文，1654 × 2339 | 3.649 秒 | 0 / 373 字符 | 7 / 7 |
| 轻微失真的双栏中英文，1290 × 1824 | 6.471 秒 | 1 / 354 字符 | 12 / 12 |

双栏页面中的规则表格网格形状与 16 个单元格内容均匹配，9 个数字值均识别；该页公式在 LaTeX 归一化后与参考答案一致。两页返回的矩形均通过坐标范围检查，公式仍保留待核对标记。上述数据只说明这两张合成样本的结果，不代表真实资料的正确率、持续吞吐或复杂表格能力；页耗时不包含应用侧 PDF 渲染、网络传输与索引。

另有 11 项服务单元测试通过，覆盖输入与输出约束、profile 标识、无文字图像保留、图像与重叠文字区域不丢字且不重复、工作进程退出恢复及初始化失败退避。合成图片和原始验收输出保存在临时测试目录，不作为生产资料或配置提交。

同日对最终 `high-quality-v2` / `3.7.0-hq2` GPU 服务进行了 HTTP 复验，通过容器内回环 HTTP 调用相同的两张合成图片：

| 合成页面 | HTTP 请求耗时 | 归一化文本编辑距离 |
| --- | --- | --- |
| 单栏中英文 | 3.796 秒 | 0 / 373 字符 |
| 轻微失真的双栏中英文 | 6.467 秒 | 1 / 354 字符 |

v2 返回坐标均通过范围检查；双栏页的表格仍为 16 / 16 单元格匹配，公式仍在 LaTeX 归一化后匹配。此次耗时包含 HTTP 请求处理，不包含 PDF 渲染及索引，不能与首轮直接推理耗时视作同一口径。此次未重新测量初始化耗时或内存，上述 32.598 秒和 2508.8 MiB 仍仅属于 v1 记录。两张样本均没有图像区域，因而不验证真实模型的图像检测或裁图链路；v2 图像块输出行为目前由上述单元测试覆盖。
