# 笔记编辑器迁移：md-editor → 块编辑器（语雀式）

> 起因（2026-09-30）：代码块要求「预览里直接写、行号立刻出现、光标正常」，而现架构做不到。
> 结论是**架构问题**，不是补丁问题 —— 用户决定按语雀的设计做迁移。
> 本文件是这次多轮迁移的落点：每轮更新「进度」，任何一轮中断都能从这里接着做。

## 为什么现架构做不到（诊断，别再重复踩）

现链路：`Markdown 文本 → markdown-it 渲染 HTML →（直接在 HTML 上 contenteditable 编辑）→ 反推回 Markdown`

- **行号没有归属者**：行号是"渲染完再后处理 DOM"加的，md-editor 一重渲染（改内容/切主题）就整个重建；
- **拆行必然丢光标**：光标是浏览器 DOM 选区，重排 DOM 时浏览器不会映射回去（ProseMirror 会，因为它的选区是**模型位置**）；
- **内嵌编辑器被抢焦点**：预览整体是 contenteditable，插进去的 CodeMirror 也是 contenteditable；点一下冒泡到预览的 `focusin` → 进入预览编辑态 → 可能触发重渲染 → 编辑器实例被冲掉。

已尝试并**失败**的四条路（不要再走）：

1. 另画一栏数字 → 重渲染留孤儿节点 → `1,1,2,2,3,3`
2. 按行拆 DOM → 打字重排丢光标；不重排则新行无号
3. 内嵌 CodeMirror 覆盖层 → 抢焦点 → 无光标 + 回车双插
4. 拆行 + 光标保留 → 重排把**行号当代码文本吞进内容**（14 行渲染成 28 行）
   —— 已下线（commit `acd2b80`），并核查过笔记 44/51 **未被污染**（0 条）

## 目标架构（对齐语雀）

```
文档模型（ProseMirror JSON，唯一真源）
   └─ 每个块是一级节点：段落/标题/列表/引用/表格/代码块/图片/提示块/折叠块…
        └─ 代码块节点 = { language, text } + **CodeMirror node view**（行号/光标/编辑都由它管）
```

关键：**代码块有主人**（节点 + node view + 模型选区），所以行号与光标不会再被重渲染打断。

## 风险与护栏

- **数据安全**：笔记以 Markdown 存储，任何阶段都必须保证「模型 → Markdown」往返无损；
  进入 Stage 1 前先做**往返测试集**（取真实笔记做样本，逐篇比对转换前后）。
- **不破坏现状**：新路径始终在开关后面，默认关闭；每轮结束必须 `npm run build` 通过 + 真机验证。
- **依赖**：`@codemirror/*` 目前是传递依赖，迁移时一并显式写入 `package.json`。
