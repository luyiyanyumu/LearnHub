# 知识库分块

默认使用结构切割。进入「设置 → 知识库 → 切块与索引」可以选择长资料语义切割；保存切块参数后，需要完成索引重建才会使用新的分块边界。

## 结构保护

- 先识别 Markdown 标题，再按自然段和完整句子组织普通文字。
- 代码围栏、多行展示公式、常见 LaTeX 数学环境、Markdown 与 HTML 表格作为完整结构保留；它们内部的标题和空行不会触发拆分。
- 结构模式直接按自然段和完整句子组织正文，不使用语义边界计算所需的小文字单元。目标长度是软目标；完整句子、公式和紧邻解释在最大长度以内可一起保留，避免为了卡住目标长度而过早拆分。
- 重叠只复制完整的文字句尾或完整保护结构，不复制半句话、半个代码、公式或表格。普通文字受最大长度限制；只有单句也超上限时才在词边界附近兜底切开。单个保护结构可以超出普通文字上限，独立保存。
- Word 的检索文本保留标题层级、段落空行和表格单元格结构；阅读器展示结构不受影响。已经抽取过正文的 Word 文件，需要重新抽取正文才能得到这种格式，仅重建向量不会重新解析原文件。纯文本 PDF 未恢复出的版面和表格，分块器不能凭空还原。

超长保护块的完整原文保存在索引中，但嵌入仍受「嵌入文本上限」限制，超出的输入只嵌入前缀。组装回答上下文时，保护结构必须完整放入预算；放不下的结构会整体跳过，不会为了填满预算发送半段公式或代码。因此内容完整性不等于所有超长结构都能被一次完整召回、注入。

## 可选语义切割

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `chunkStrategy` | `structure` | 可选 `semantic_long`；只对上传资料 `file` 生效 |
| `semanticMinChars` | 4000 字符 | 达到此长度的资料才计算语义边界 |
| `semanticBreakpointPercentile` | 85 | 按同小节相邻文字单元的语义距离选取候选切点 |

笔记、速查卡和短资料继续使用结构切割。语义模式使用当前嵌入模型，在入库时计算普通文字单元的向量；代码、公式和表格不参加语义边界判断。它保留标题边界、最小聚合长度、目标长度与普通文字上限，不跨主题边界带入重叠。

模型调用失败会终止本次准备，旧的已提交索引仍保留。语义切割会增加构建耗时，不会在普通提问时重新调用模型计算分块边界。

## 入库和查询的一致性

完整分块正文、小节和序号保存在 `kb_chunk`，来源指纹包含正文、标题、嵌入空间、分块算法版本及配置。查询先校验来源指纹，再复用已存分块；关键词、向量、Wiki 定位、图谱证据与相邻块扩展使用一致的边界。

内容、标题或配置发生变化时，当前正文仍可按结构切割参与关键词检索；过期向量不能进入融合，也不能先影响有效向量的相对分数筛选。索引状态和分块正文在同一只读数据库快照中读取。进程重启后仍可从数据库恢复边界，无需重新进行语义切割。

数据库迁移 V7 将较小的正文列扩大到 `MEDIUMTEXT`，用于保存超过 64 KiB 的完整保护结构；不会缩小已有列或改写原有正文、向量和来源状态。

## 检索时补齐相邻原文

回答上下文先保留实际命中的片段，再在相同来源、小节内检查前后两块。即使只允许补一块，也会比较两个方向，优先补充问题中尚未被命中正文覆盖的概念，而不是固定先补后文。相同相关度沿用后文优先的顺序，兼顾定义后接示例的资料。

没有小节标题的导出文本不构成可靠的主题边界，因此只补入含问题词项的邻块。邻块仍受单段和总上下文预算限制，不挤掉已保留的命中片段，不增加引用条目上限；代码、公式和表格必须完整放入预算。实际引用记录只包含最终展示的原文摘录。

对于没有标题元数据的资料，还可从正文中的裸编号识别保守的章节层级：必须有明确的根章节、非根父节和至少两个有序子节；代码、公式和表格中的编号不参与识别。每个回答最多补入一个与问题词项相关的父小节开篇，优先于普通邻块，并与邻块共用数量额度。父块必须整块放入单段与总预算，不能放下就跳过，所有原始命中仍保留。父节使用独立标签和原始片段序号记录，不作为相邻块展示；已有标题元数据的来源继续沿用原有边界。

这个步骤只使用本地文字匹配和章节层级，不新增模型调用，也不改变分块或向量内容，因此无需重建索引。它能补齐直接相邻或具有明确父子层级的原文；缺乏这种结构的远处段落，仍需要单独评估召回策略。

## 对比结果

见 [31 题合成资料对比报告](chunking-benchmark-2026-10-26.md)。这是与报告内源码指纹对应的历史基准，后续边界修复需要按新版本重新评测。该实验使用真实 Java 分块实现和本机 Qwen，固定题库、模型、切块参数和检索正文预算，隔离分块对纯向量检索的影响。它没有测量端到端回答正确性，不能推断当前私有资料的稳定收益。真实资料的复测正文、题目、向量及结果保留在仓库外，不写入示例或提交记录。

目前结构完整性改善有直接证据；长文语义切割的额外召回收益仍不足以支持默认开启。
