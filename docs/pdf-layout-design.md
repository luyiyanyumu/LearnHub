# 抽取正文：把 PDF 的"版面"还原成可读的正文

阅读器里的「抽取正文」不是把 PDFBox 的 `getText()` 直接倒出来 —— 那样得到的是**双栏串行**、
**图表数字混进正文**、**代码块碎成几十行一句**的一坨文本。这一层做的是**版面还原**：
把 PDF 的字符坐标重新组织成"标题 / 作者 / 小节 / 段落 / 列表 / 代码 / 表格 / 元信息"。

所有数字都来自对 `backend/uploads/` 里 **5 份真实样本**（两篇 RAG 论文、一篇 Agent 论文、
一篇 47 页论文、一本 96 页中文讲义）跑同一段代码的前后对比；回归用例是
`PdfLayoutExtractorTest`（断言**与版面无关于**，见 §4）。

---

## 1. 流程：从字符到块

`PdfLayoutExtractor` 一页一页处理，每页走这 9 步：

| # | 步骤 | 关键实现 |
| --- | --- | --- |
| 1 | 收集"行 → 词" | 重写 `PDFTextStripper.writeString(text, positions)`；**必须同时重写词/行分隔回调**，否则空格全丢（踩过） |
| 2 | 估正文字号 | 按**字数加权的众数**（0.5pt 一档）：标题、脚注是少数派，不该拉偏基准 |
| 3 | 检测中缝 | 给"同一行里的大空隙"投票，票数最多且落在页面中部（28%~72%）的算中缝；**支持率要 ≥ 整页行数的 25%**，否则视为单栏 |
| 4 | 找正文起始 y | 标题区与正文的分界线：**最后一个"字号更大 + 够宽"的行**之下，第一个"够长 + 贴栏边"的行 |
| 5 | 分流 | 行内先按中缝切，再判断属于左栏 / 右栏 / 通栏（居中块整行当通栏，不切） |
| 6 | 拼段落 | 行距 / 首行缩进 / "上一行没写满且以句末标点结束"三条规则断段，其余情况把行拼回去 |
| 7 | 分类 | 逐行判 `heading`（编号 / 词表 / 加粗且大一号）、`code`（等宽字体 + 形态）、`table`（连续 3 行以上的"表格行"）、`note`（页面底部的小字脚注），其余进段落 |
| 8 | 插图 | 扫出这一页每张**位图**被画在哪（CTM 包围盒），按 y 插进正文流 —— 图里的字不"识别"，直接裁原图（见 §5.1） |
| 9 | 丢页眉页脚 | 跨页重复出现的短行（归一化后出现 ≥ 3 次）、页边 arXiv 水印、页码 —— 按出现频率丢弃 |

段落拼接的**断**判据（`paragraphBreak`）：

- 段间距：`gap > max(1.55 × 字号, 1.45 × 本栏实测行距)`，并封顶在 `2.5 × 字号`；
  行距取"相邻行 y 差的 40% 分位" —— 用中位数会被段间距抬高；
- 首行缩进：本行缩进 > 0.55 字宽、< 栏宽 25%，且**上一行没有缩进**（只和上一行比，
  否则摘要区整体缩进会把每一行都当成新段落）；
- 上一行以句末标点结尾，且右边距还空着 1.6 字宽以上（说明它是本段的最后一行）。

## 2. 这轮修掉的 11 个"识别得差"

| # | 现象（实测） | 原因 | 修法 |
| --- | --- | --- | --- |
| ① | 某篇论文**一个标题块都没有**，大标题变成 `[meta]` | 横排的 arXiv 标记是 20pt，比 17pt 的标题还大，抬走了"最大字号" | 算最大字号时排除 arXiv 标记 |
| ② | 柱状图数字变成 `[heading1] 60 68.8 72.3` | 图表刻度短、加粗、字号更大，和标题长得一样 | 标题必须"以文字为主"（字母数 ≥ 数字的一半）、长度 ≤ 60、不以数字开头、单个拉丁词不算 |
| ③ | 正文里的 `2016 world leaders and 68% …` 变成 `[heading1]` | 编号小节的判据太松（只看"数字 + 空格"） | 章节号首段必须 ≤ 30；整行 ≤ 70 字、≤ 12 词；编号后面必须是"标题词"（大写/数字/汉字/括号） |
| ④ | 中文讲义被**按行切碎**：1119 段、平均 39 字 | 断段只和字号比（1.55×字号），行距 1.6 倍的书里"相邻两行"就超了 | 断段同时参考本栏**实测行距**（§1） |
| ⑤ | 一页 JSON 变成 17 个 `[para]` | 代码/数据区的行距比正文松，2.2×字号就把每行判成新段；且页首几行被划进"标题区"后逐行落块 | 代码段的间隔判据改用行距；**非首页不再走标题区**，页首通栏行按正文合并 |
| ⑥ | 结果表被拆成几十个一句一行的段落 | 拼段与"表格行"没有区分 | 新增"表格行"累积：短、无句末标点、无汉字、以大写/数字/符号开头、**不顶到栏右边界**、且每个词都以大写/数字开头；连续 ≥ 3 行 → 一个 `table` 块 |
| ⑦ | 页面底部的三条脚注黏成一段，读起来像乱码 | 脚注被当成正文的续行（`para` 只认"短 + 贴底"，且段落正在拼时不切） | 字号 <0.85 倍正文**且**在"最后一行正文"之下、且页面底部区；**带 ∗/†/‡ 标记的行不看字号**（§5.2） |
| ⑧ | 图表里的字被"识别"成散落的段落 | 位图里的文字也能抽，但抽出来没有语义 | 不识别，按 CTM 包围盒把原图裁出来贴回原位（§5.1） |
| ⑨ | 脚注与正文**同一条基线**时被拼成一段（"∗These authors contributed equally. real-world engineering resources…"） | PDFBox 按基线并词，脚注与正文落在同一行 | 行内按字号切两刀（§5.2），切开后脚注按小字/标记落 `note` |
| ⑩ | 脚注首字母被吃掉（"These" → "hese"），整条脚注落不了块 | 去标记的正则写成 `^\s*(标记)\s*\S.*`，`replaceFirst("")` 把正文一起删了；`NOTE_SYMBOL` 末尾的 `\S` 又让 `matcher.end()` 多吃一个字母 | 正则只匹标记本身，用 `end()` 截断（§5.2） |
| ⑪ | 附录公式与正文混排，式子被两栏拼成一行 | 公式行投票太少，中缝估计偏了十来点；公式字号忽大忽小 | 中缝容差放宽到 `gap/2+12`；连续的公式行合成 `formula` 块（§5.3） |

## 4. 回归测试：只断言"与版面无关于"的性质

`PdfLayoutExtractorTest` 对**每一份**样本跑下面这些断言（没有样本时自动跳过）：

- 状态 `ok`、每页有块、块不空、双重编码乱码已修（`â€“` 这类）；
- 纯数字块占比 < 10%（页码噪声信号）；
- **最长正文块 ≥ 300 字**、≥ 3 个 ≥ 300 字的块：一行装不下 300 字，能拼出 300 字就证明真的成段了；
- 平均段长 > 40 字（兜底）、短块占比 < 60%（拦"失控"级别的切碎）；
- `heading` 块不能以数字为主（挡图表刻度）；
- `table` 块必须多行（单行的"表格"只是误判）；
- 有 `title` 块时，它不能是页边 arXiv 水印。

**为什么强调"与版面无关于"**：这组用例最初写的是"第一份样本必须两栏、必须有 title/authors"
—— 那是照着某一篇论文写的，后来库里多了一篇单栏论文（文件名排前面），提取结果完全正确却把用例跑红了。
后来又犯过一次：把"最长段 > 600 字"当判据，96 页的中文讲义最长段只有 360 字，同样跑红。
**拿单个样本的版面特征当断言，测的是样本，不是代码。**

## 5. 图与脚注：不硬"识别"，按位置贴回原文

### 5.1 插图（`figure` 块）

图表、流程图、公式截图里的文字**不该被抽成正文** —— 抽出来只会是散落的碎片（实测某篇论文的柱状图
刻度变成了 `[heading1] 60 68.8 72.3`）。做法是把原 PDF 里那块图**按位置裁出来**贴回正文：

| 环节 | 实现 |
| --- | --- |
| 找位置 | `PdfFigureScanner` 继承 `PDFGraphicsStreamEngine`、重写 `drawImage(PDImage)`，把单位正方形四角经 CTM 变换取包围盒 |
| 换算坐标 | CTM 的 y 是 **PDF 用户空间**（原点左下、y 向上），正文行的 y 是"从页面顶部往下"（PDFBox 的 `getYDirAdj`）—— 必须翻一下（`pageHeight - maxY`），否则整页错位半页（实测踩过） |
| 过滤噪声 | 短边 < 24pt 或不足页面 1% 面积的不算图（分隔线、图标、页边 logo）；被更大的框盖住 80% 的重复绘制去重 |
| 贴回正文 | `columnPlaced` 按 y 把图插进正文流（不是堆到页尾）；双栏页按 x 判定属于左栏 / 右栏 / 通栏 |
| 裁剪接口 | `GET /api/files/{id}/page-image?page=&idx=`：150dpi 渲染该页 → 按 `dpi/72` 缩放裁一刀 → 缓存到 `uploads/.derived/<id>/p<页>-<序号>.png` |
| 前端 | `figure` 块渲染成 `<img loading="lazy">`（工具条顺带提示"含 N 张插图"），不进翻译链路 |

**只有位图（embedded image）能这样裁。** 用矢量画出来的图表（不少论文的柱状图、不少中文技术书的插图）
没有对应的位图对象；要认出"这块矢量图形是一张图"得再做一层图形聚类，现在不做 —— 那些图的刻度文字
仍可能作为短块出现在正文里（但已经不会冒充标题了）。

**扫描页**：整页没文字但有图时，直接把这页当一张图交给界面，而不是只回一句"扫描件需要 OCR"。

### 5.2 脚注（`note` 块）

论文底部的脚注原先被当成上一段正文的续行，两三条脚注黏成一段 —— 实测某篇论文首页是
`∗Equal contribution 1The code and trained models have been released at …` 这一坨。

现在的判据（按顺序）：

| 判据 | 内容 | 为什么 |
| --- | --- | --- |
| 页脚区 | 行的 y **必须大于**"这一栏最后一行正文字号的 y" | 技术书里的提示框/代码字号也小，却夹在正文**中途**；不加这一刀，某本 300 页中文讲义的代码示例会被整段收成脚注 |
| 位置 | 页面 ≥85%（小字）/ ≥82%（带标记） | 正文最后几行同样贴底，位置门槛不能省 |
| 小字 | 无标记行要求主导字号 <0.85 倍正文；编号脚注和已确认续行允许 <0.95，最大字号仍不超过正文 | 不仅凭小一档字号分类，带编号与续行还需满足页脚位置、正文边界及相邻几何条件 |
| 标记 | 行首 `∗ / † / ‡` 或编号（`1The code…`、`1 The code…`） | 同字号的符号脚注由标记与页脚位置判断；编号脚注仍需满足小字条件 |
| 排除 | 等宽占比 ≥40% 的行不是脚注 | `looksLikeCode()` 认不出 Python 片段（`best_idx, best_score = None, -1e9`），等宽字体是更可靠的证据 |

**去标记只去标记**：正则写成 `^\s*(?:[*∗†‡§¶]+|\d{1,2}…)\s*` 并只取匹配区间，正文一律保留。
展示脚注时保留标记，便于与正文编号对应；以上去标记规则仅用于工具函数。
这里踩过两个坑（都已写成回归用例 `PdfFootnoteRulesTest`）：

1. 早先写成 `^\s*(标记)\s*\S.*`，`replaceFirst("")` 会把**正文一起删掉** ——
   `∗These authors contributed equally.` 去标记后剩空串，脚注再也落不了块；
2. `NOTE_SYMBOL` 末尾多写了一个 `\S`（当时只想"确认后面还有字"），
   而截断用的是 `matcher.end()` —— 那个 `\S` 正好是正文首字母，
   于是 `These authors…` 被削成 `hese authors…`。**判定用的正则和截断用的正则必须是同一个。**

**脚注与正文同基线**：PDFBox 按基线并词，脚注和右栏正文会落进同一行（实测首页 87% 处是
`∗These authors contributed equally. real-world engineering resources, to evaluate task com-`）。
处理办法是行内**按字号再切一刀**（`splitBySize`）：两词字号差 >0.4pt、水平空隙 >1.6 倍小字号、
且双方都 ≤0.9 倍正文才切，**切出来的每段至少两个词**（单字符碎段一定是误切 —— 就是它把 "T" 切走过）。

**连续脚注合并**：`1The code and trained models have been released at` +
`https://github.com/facebookresearch/DPR.` 是**同一条**脚注折成两行，按
"没有新脚注标记 + 基线相邻 + 左边界允许悬挂缩进"合并；`∗Equal contribution` 与
`1The code…` 有不同标记，不会被并。行基线按文字数量取中位数，避免上标编号放大行间距。
续行中的断词连字符按正文规则拼回单词。
独立抽成一行的上标编号，会与紧邻的小字正文合并；单独的页码不会进入脚注。

### 5.3 公式（`formula` 块）：不做 LaTeX 还原，但"看得见、不混进正文"

PDF 里没有"公式对象"：公式是散落在坐标上的一堆字形，上下标字号还不一样，抽出来必然是
`(θ|q) R(q o … KL …)` 这种粘连的碎片。**不承诺 LaTeX 化**，做三件能确定的事：

| 环节 | 实现 | 实测效果 |
| --- | --- | --- |
| ① 字形名换回符号 | 数学字体（CMMI/CMSY/CMEX…）缺 `ToUnicode` 时 PDFBox 会抽成 `?`，但**字形名是好的**（它自己的警告里写着 `No Unicode mapping for lessmuch (28)`）。于是 `PDFont → Encoding.getName(code)` 取字形名，再查一张数学字形表（80 条左右） | 作者行里的 `?` 变成 `†‡⋆`，`θ⋆`、`≪` 这类符号回来了。全库 6 份 PDF 只有 5 种缺映射字形，收益主要在同类论文上 |
| ② 公式块按**原图**渲染 | 公式块带 `page` + `rect`（pt）；前端拼 `/api/files/{id}/page-image?page&x0&y0&x1&y1`，后端把该页渲染成 150dpi 再按矩形裁一刀（与插图同一套缓存） | 式子的排版、上下标、求和号与原 PDF **一致**；抽出来的文本附在下面，可复制、可搜索 |
| ③ 判据防误伤 | 紧凑变量等式单独识别；其他行要求短、不以句末标点结尾、数学符号 ≥3 个且密度 ≥13%。排除模板/HTML，等宽字体赋值语句保留为代码 | `E=mc^2`、`x+y=z` 可以独立成块，说明句和提示词模板不会仅因含等号就被截走 |

**几何取字形边界的并集**：收集每个字形的上下边界并留少量边距，再合并紧邻且水平重叠的公式碎行。
不能只用首字基线或行数字号估算高度；`max`、期望符号及上下标可能分散在多条抽取行中。
裁图按实际像素边界缓存，并与页面边界求交；无效页码、非有限坐标及页外区域会被拒绝。

> 仍会退化的地方：字体映射被吃掉时（`?`）① 也救不回来（不是每种字体都有可靠字形名）；
> ③ 的判据刻意保守 —— 宁可漏判（留在正文里），也不把正文里带等号的一句话割出来。

## 6. 还剩什么（不打算靠猜解决的）

- **数学公式区**：现在能"单独成块 + 按原图贴出来 + 找回缺映射的符号"，做不到 LaTeX 化；
  公式行在正文里被拆得太碎时（一行里混着说明文字），判据会保守地不认它，仍是普通段落；
- **技术书里的"小字提示框/代码块"**：它们字号也比正文小一档，位置又可能贴底，
  仍会被判成 `note`（实测某本中文讲义偶发几处，每页 1~3 块）。判据里"页脚区"那一刀挡掉了大部分，
  但这类版面与真脚注在几何上确实不可分；
- **字体本身坏掉的乱码**：个别 PDF 的代码字体没有完整的 `ToUnicode`，
  抽出来就是 `çæ¨¡åæ¬` 这种**残缺字节序列**（不是规范的"UTF-8 被当 Latin-1"），
  `repairMojibake` 只能修规范的那种，残缺的修不了 —— 除非上 OCR；
- **跨页段落不接**：段落在页脚被切断后，下一页会另起一段（每页独立处理）；接起来需要
  "页脚行未结束 + 下一页首行小写开头"的判断，误判风险不低，暂不做；
- **表格只是"按行还原"**：给出的是"一行一个原文本行"，不是真正的行列结构，
  合并单元格、跨列表头都没有还原；
- **矢量图不裁**：见 5.1；
- **扫描件**：整页是图、没有字符可抽，靠 5.1 的整页贴图降级展示（不是 OCR）。
