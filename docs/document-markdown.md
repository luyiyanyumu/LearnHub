# 资料的统一 Markdown 与来源定位

LearnHub 将资料转换为结构化 Markdown，再从通过质量检查的内容生成检索正文。原生格式管线与高精度逐页扫描管线都分别保存原文展示结构与检索投影，避免把模型补充内容当作原文。配置本地结构化扫描后，PDF 与栅格图片默认使用 `document-ingestion-v5-scan-hq2`，包括有文字层的 PDF；Office、Markdown、纯文本等仍使用对应原生解析器。上传原件保持不变；Markdown、图片及定位 JSON 是与原件版本绑定的派生结果。Markdown 会随阅读宽度重排；精确分页、字体、浮动位置和整体排版以原件为准，不逐像素复刻。

## 在资料库中使用

1. 上传资料后，打开「阅读 → 结构化 MD」。默认显示与当前原件匹配的最新扫描结果；没有待发布候选时使用已发布结果。可切换「预览」「源码」「按块核对」，或切回当前检索版本对照。
2. 「复制 MD」「下载 MD」使用当前选择版本的完整展示 Markdown。「下载图片包」导出同一版本的 Markdown、定位 JSON 和图片。版本已经变化时要求刷新，不悄悄下载另一份结果。
3. 在抽取报告中核对来源、警告、未通过的候选及未处理范围。公式或图像描述来自模型时，对照原图检查数字、变量、单位及图表含义。
4. 若图片或公式尚未处理，可点击「处理公式与图片」；已有处理记录时显示「继续处理公式与图片」。后台任务会显示实际状态，关闭阅读器不会取消任务。
5. 已启用高精度扫描时，可在「抽取报告」点击「重新扫描」；尚有未完成扫描页时使用「继续扫描」。旧资料升级期间，主 MD 可阅读新扫描结果和查看扫描进度，检索继续使用原有可用正文；阅读、复制和下载不会发布候选。
6. 新扫描正文的公式转写、低置信度文字及图片扫描问题在对应段落旁显示「待核对」按钮，可进入同一版本报告查看证据。公式确认只更新候选；检索入库需另行审核，完整性和已有可靠公式的保护仍生效。审核只收录合格内容，其余不确定文字继续排除。

旧资料没有当前版本的 Markdown 时，阅读器会保留原件与旧正文，并提供「生成结构化 MD」。资料库顶部的「更新已有资料的 MD」用于显式批量转换，升级或打开阅读器本身不会自动批量转换历史资料。

## 展示 Markdown 与检索 Markdown

| 结果 | 用途 | 保留内容 |
| --- | --- | --- |
| 完整展示 Markdown：`markdown` | 阅读、复制、下载、人工核对 | 原文标题、列表、表格、代码、原生公式、按源顺序放置的原图，以及真实页边界；缺失图片保留占位 |
| 已发布检索 Markdown：`text`，读取接口中为 `indexedMarkdown` | 结构分块、关键词及向量检索，供后续图谱、Wiki 等读取 | 当前实际检索版本中的合格块；不会因主 MD 改看候选而变化 |
| 当前阅读版本的合格投影：`reviewMarkdown` | 审核时核对可收录内容 | 所选扫描结果中通过质量检查的块，候选尚未入库时不代表当前检索正文 |

主展示正文以原文为主。模型新增的图像描述、解释性文字或派生公式保存在定位 JSON、检索投影及「按块核对」中，不重复插入主正文，不把同一原图再追加成「图 + 模型公式」大段内容。原生 OMML 或可靠原生公式按原位置展示 LaTeX；公式本来是一张图片时，正文保留该原图及尺寸，识别出的 LaTeX 单独用于核对和检索。预览依据同一版本的块偏移显示待核对标记，不改写复制或下载的 Markdown，也不拆开表格、代码及公式。

图片地址、资产哈希和普通链接目标从检索投影中去除，保留有意义的可见说明或链接文字。泛化的「原图」标签及待处理提示不作为知识正文。代码围栏、行内代码和数学表达式保持完整，不把其中看似链接的程序文本当作图片路径清理。

以下为合成文档的展示 Markdown 示例；图片名仅作占位，实际名称由图片内容的 SHA-256 生成：

````markdown
<a id="source-page-3"></a>

###### 印刷页码 iv · 原件第 3 页

# 合成实验：传感器平均值

| 样本 | 读数 |
| --- | --- |
| A | 12 |
| B | 16 |

$$
\bar{x}=\frac{1}{n}\sum_{i=1}^{n}x_i
$$

观察图示 <img src="assets/<sha256>.png" width="240" height="96" alt="原图"> 后比较两组读数。

> 合成原文引用：测量条件保持一致。

原文说明见[实验方法](https://example.org/synthetic-method)[^sample]。

[^sample]: 本示例仅包含合成数据。
````

示例中的页标记只用于展示，不进入检索；图像路径也从检索投影中去除。脚注正文和安全链接的可见文字仍可检索。假如图片模型另返回一段图像描述，该内容会进入 JSON 与可靠检索投影，不自动填在图后充当原文图注。

图片显示尺寸采用 CSS 像素，与 PNG 的光栅分辨率、PDF 页宽分开保存。优先使用原文的图片尺寸；PDF 可从原图区域的 pt 尺寸换算为 CSS px。行内图片保留在所属段落的位置，过宽图片随阅读区域缩小并保持比例，尺寸上限为 4096 px。浮动对象只能近似按源顺序重排，需精确对照时返回原件。

## 各格式的结构保留

| 格式 | 当前转换方式及边界 |
| --- | --- |
| PDF | 配置结构化扫描后，所有非空页默认逐页扫描，包括有文字层的页面；未配置时保留文字层优先及基础 OCR 回退。保留检测到的插图、图表原始区域图片及真实页边界，有 PageLabels 时同时显示印刷页码与原件物理页序号；复杂阅读顺序仍须核对 |
| 栅格图片 | 配置结构化扫描后默认逐帧扫描；保留对应帧原图与像素定位。未配置时使用已启用的基础 OCR；没有可靠文字时仍保留展示结果与失败原因 |
| Word：docx / docm | 按文档顺序原生解析标题、列表、表格、OMML 公式和可提取图片，保留可识别的显式分页；表格保留空单元格。嵌入图片的可见文字优先使用已配置的本地高精度模型识别，不把 Word 整篇转成扫描图。不会推测 Word 自动分页或印刷页码。旧版 `.doc` 使用兼容文本提取，复杂对象需查看原件 |
| Excel：xlsx / xlsm / xls | 保留工作表边界、列位置、空单元格及可提取图片，以表格表达；不重现整个工作簿的样式或交互 |
| PPT：pptx / pptm / ppt | 保留幻灯片边界、文字、表格和可提取图片；不重现动画、完整主题及任意图形组合 |
| Markdown | 保留引用、脚注、安全链接及已有软硬换行，过滤不安全 HTML；外部图片与本机路径不会因预览自动访问 |
| 文本、CSV / TSV、源码 | 文本按段落组织，分隔表格保留空列；已识别的源码使用相应语言的完整代码围栏 |

普通表格使用 GFM；需要保留的安全表格 HTML 可继续呈现。原生可靠公式使用 LaTeX，行内公式与独立公式分别保持原有位置，独立公式以 `$$...$$` 输出。不把猜测的 LaTeX 当作检索正文。原始 Markdown 的软换行按标准段落语义呈现，两个行尾空格或反斜杠产生显式硬换行；格式适配器也区分可识别的显式换行与视觉折行，避免把每条 PDF 行都强制断开。

PDF 的原件第 N 页是从 1 开始的物理页序号。若文件提供 PageLabels，则另显示印刷标签，如「印刷页码 iv · 原件第 3 页」；没有标签时不猜印刷页码。页锚点与页标签仅属于展示 MD。Word 的显式分页、工作表和幻灯片边界也不等于自动印刷页码，不伪造精确 PDF 区域坐标。

## OCR、图片与公式模型

本地扫描、基础文字 OCR 与图片模型分别配置：

- 本地 PP-StructureV3 扫描服务配置后成为 PDF、图片的默认路径，识别版面、文字、表格和公式。已有文字层不会跳过扫描；公式候选仍需核对确认，服务健康不表示识别结果正确。服务支持 CPU 和 GPU，已验证的 GPU 配置使用 `device=gpu:0`；具体部署与 CPU 内存限制见 [本地文档扫描与 OCR](document-ocr.md#默认高精度逐页扫描)。
- 可选的本地 Tesseract 侧车识别中英文文字，部署与清洗规则见 [本地文档 OCR](document-ocr.md)。它不需要 API key，不恢复可靠的数学 LaTeX 或表格语义。
- 图片与公式处理复用「模型参数 → 公式原图识别」的现有模型档案，需支持图片输入。它可返回可见文字、图片描述和 LaTeX，不新增独立嵌入模型。若该档案连接外部服务，待识别的图片会发送给该服务。

新上传或重新抽取资料时会执行媒体处理；单独重试媒体时可复用已保存的区域和缓存。没有可用图片模型时仍尽量提取原图，并明确标为待处理；打开原文、切换 Markdown 视图或读取报告不会启动模型调用。

Word 等格式保持原生解析，嵌入图片在媒体阶段优先使用已配置的本地高精度服务提取可见文字及可用表格文字；未配置时使用已启用的基础 OCR。这里不会把未核对的本地公式候选直接并入检索，已有 OMML 和可靠公式仍保留。`3.7.0-hq2` 的 GPU HTTP 复测已在两张合成页面上复现前版的文字、表格和公式识别质量；样本不含插图，图像区域保留另有单元测试覆盖。具体结果与边界见 [侧车验证记录](../tools/document-structure/README.md#合成样本验证记录)，不能据此推断所有真实文档的识别质量。

Office 图片的本地结果按文字块校验：合格文字可以补入检索，少量低置信度文字或待核对公式不会使整张图的合格文字被丢弃；不可靠部分仍不进入索引，原图与旧可靠内容保留，整图保持待核对状态。待核对结果会随同源、同模型版本的缓存复用，不反复请求模型猜测。图片已扫描、识别结果已全部采纳是两种不同状态。

图片模型返回值须通过结构、长度、公式安全等检查；拒绝、超时、截断、格式错误或自报不确定的结果保留原图和警告，不加入可靠检索正文。`recognized` 表示模型结果通过了这些检查，不代表事实或公式一定正确。可靠的文字层、OMML、几何公式及已确认公式可继续保留，不因一次识别失败被可疑候选覆盖。

媒体处理每轮有区域数量、图片像素、文件大小和时间预算；当前一轮最多调用 12 个区域，总时间预算 180 秒，单次视觉请求最多 60 秒。到达预算后报告为部分完成，保留剩余范围；重试可复用缓存。不要将 `status=ok`、模型可调用或侧车健康当作整份资料已完整覆盖，应同时检查 `report.partial`、`report.truncated`、警告与处理页数。

显式的媒体或历史迁移后台任务会自动续跑，每份资料最多续跑 100 轮；可靠结果复用缓存。Office 本地扫描优先覆盖尚未尝试的图片，再在同一任务内对请求失败的图片最多补试一次，同图重复引用不会在同一批反复消耗调用额度。服务恢复后可显式启动新的本地任务重试请求失败的图片；已得到待核对结果的图片仍复用结果。

实际尝试过但仍需核对、请求失败、尚未尝试分别记录。旧版本缺少明确 `outcome` 的缓存和标记会重新核实一次，包括旧 `accepted`/`empty`，因为旧记录没有完整保存被跳过的公式候选；具有新分类的同源、同模型版本结果随后正常复用。新增尝试也计为任务进展，不会因为前几张失败就让后面图片一直轮不到。没有新的尝试或可靠结果、也没有可执行的有界重试时，任务停止并保持部分完成，不为清空计数而接受不确定结果。

图片很多时任务可持续较长时间，关闭阅读器不会停止后台处理。PDF 扫描和基础抽取分别受自身批次时间、页数、像素、块数和字符预算约束，具体见 [本地文档扫描与 OCR](document-ocr.md)；兼容迁移不会把旧版仅前 300 页的正文误称为完整原件。

## 原件、定位 JSON 与导出

原件继续通过资料行的「下载」获取。派生数据保存在上传目录的 `.derived/<资料ID>/` 下，包含版本化 Markdown、抽取证据、图片及识别缓存，随现有上传目录备份；不要只备份数据库而漏掉上传目录。

「下载图片包」的 ZIP 内容为：

```text
document.md
locations.json
assets/
  <sha256>.png
```

ZIP 不包含上传原件。单独下载 MD 也不包含图片字节；需要离线查看相对图片时，解压图片包并保留目录结构。没有可导出的图片时，包中可以没有 `assets/` 条目。

`locations.json` 包含两份 Markdown、原始与清理文本、模型补充内容、质量报告，以及每块的页号、可用矩形、来源方式和原件 SHA-256。展示元数据另保存行内分组、放置方式、CSS px 尺寸及可用来源引用；PDF 页可保存印刷标签。`start/end` 指向可靠检索 Markdown；`markdownStart/markdownEnd` 指向完整展示 Markdown。只供检索的模型补充块没有展示范围；未进入检索的原文候选没有检索范围，对应范围为 `-1`，两套范围不能混用。

定位同时校验原件版本与检索正文摘要，只在已接受的正文中匹配证据；匹配时可归一化 Markdown 标记，实际定位仍返回相应原文块。被拒绝的候选不作为检索定位依据。原件或正文改变、缺少报告、无法可靠匹配时返回无定位信息，不沿用旧坐标；不能将某段 Markdown 的字符偏移直接当作 PDF 页坐标。详情见 [原文阅读与划词翻译](reader.md)。

## 历史迁移、部分完成与重试

批量迁移是显式后台任务，按资料逐份保存结果，再更新分块与索引。默认跳过当前管线版本且无需媒体重试的资料；旧版本、缺失报告及仍有待处理媒体的资料会被选中。任务状态包含 `done/total`、`failed`、`partial`、逐份结果和索引结果。

配置高精度扫描后，旧版 PDF/图片不被当作当前扫描版本。升级候选分批保存在派生目录，完整候选满足质量和覆盖条件前，旧 Markdown、可靠正文及原文定位保持可用。接口的 `pendingUpgrade:true` 和 `scanProgress` 描述待发布扫描；`scanCandidate` 可供核对新候选，原有报告仍代表已发布正文。任务 `scanMode` 标识扫描路径，`pageProgress` 表示本轮候选进度，不等于当前检索覆盖。即使旧正文已覆盖全部页面，也应按候选的剩余页继续扫描，不能把旧覆盖量当作升级完成。

已有正文或抽取报告的资料执行高精度重扫时，一律将新结果留为待审核候选；`force:true` 不替代检索审核。独立发布仍要求原件 SHA-256 相同、全部物理页已处理且可用、没有失败或被拒绝的页面、没有截断或累计容量限制，并校验旧页与新页的定位尺寸一致。已确认公式仍须保留或经过明确人工核对，不能由强制任务自动确认新公式。低置信度新块仍排除在索引外并保留在报告中；即使符合发布条件，尚有此类质量问题时报告和任务仍可为部分完成。首次上传的自动抽取与 Office 原生解析保持既有行为。

定向补扫单份资料可提交 `{"resume":true,"force":true}` 到其 `extraction-jobs` 接口，无需重新运行全库迁移。已有待审核候选时，继续扫描、强制重新扫描及公式确认仍保留候选状态，不能代替检索入库审核；完整候选无需重扫已完成页，可单独提交审核。上传原件保持不变，旧报告按内容摘要保留；正文相同但定位或版本改变时，也先归档旧报告。

需要重新生成 Markdown 并复用视觉缓存时，可提交 `{"force":true,"processMedia":false}` 迁移：按当前结构规则重新生成 Markdown，复用已有的视觉识别缓存与图片资源，不发起新的图片模型请求。已有可靠识别结果会重新并入检索投影；没有缓存或尚未覆盖的内容仍标为未完成。该选项不会绕过 `processMedia=false` 发起新的图片模型请求；配置高精度扫描后，PDF/图片仍按本地扫描规则处理，并适用上述完整候选替换条件。分块与向量索引也仍按现有配置更新，不承诺整条管线没有 OCR 或嵌入调用。

- 媒体仍待处理：先补齐本地 OCR 或图片模型配置，再对该资料处理公式与图片，或再次运行默认迁移。
- 原始抽取不完整、达到字符或页面上限：核对报告；需重新解析时使用重新抽取，或通过迁移的 `force=true` 强制处理。重试不会绕过质量门控或自动提高预算。
- 一轮模型结果不满意：默认继续处理会保留可靠缓存，优先补齐未处理区域，再重试失败候选。需重新识别可靠结果时，可通过媒体接口显式使用 `force=true`；新候选仍受质量检查约束。
- 应用重启中断任务：任务记录会提示未完成，不会自动恢复原任务线程；再次提交迁移，已完成的当前版本可被跳过。
- 新结果无法保存或不满足保留条件：保留上次可用正文与定位，任务会报告失败，不能将旧正文误认为本次转换成功。

资料可靠正文变化后，沿用既有变更事件与 [后台自动维护](knowledge-maintenance.md) 更新依赖。转换任务也会尝试更新分块与向量索引；图谱、Wiki 等依配置由维护流程继续处理，转换完成不等于这些派生结构全部完成。

**向量检索需要单独配置嵌入档案。** 只有聊天或图片模型时，可靠正文仍可用于关键词检索，但不会自动获得向量检索能力。这里索引的是 Markdown 中的文字、公式与图像描述，尚不是直接将图片编码到图文联合向量空间。检查任务的 `index` 结果及知识库维护状态，确认所需阶段实际完成。

## 接口

以下均以 `/api/files` 为前缀；任务接口返回任务 ID，后续轮询状态。`GET` 读取已有结果，不执行转换。

| 接口 | 用途 |
| --- | --- |
| `GET /document-extraction/capabilities` | 本地 OCR、结构化扫描和图片模型的可用状态；扫描配置后返回默认扫描模式 |
| `GET /{id}/markdown` | 默认 `version=latest`，也可指定 `published` 或 `candidate`；返回所选 `markdown`、`pages`、资产、审核状态及当前已发布 `indexedMarkdown` |
| `GET /{id}/extraction` | 完整抽取与定位证据 |
| `GET /{id}/markdown/download` | 下载所选版本 `document.md`；支持 `version`、`sourceRevision`、`artifactRevision` |
| `GET /{id}/markdown/bundle` | 下载同一所选版本的 Markdown、定位 JSON 与图片 ZIP；版本参数同上 |
| `POST /{id}/reextract` | 重新解析原件并处理媒体 |
| `POST /{id}/extraction-jobs`，正文 `{"resume":true}` | 后台继续未完成页；配置扫描时 PDF/图片使用默认扫描路径；`resume:false` 主动重新处理。可选 `force:true` 允许完整同源 HQ2 候选更新旧自动正文，仍受页面完整性与公式保护校验 |
| `GET /extraction-jobs/{job}` | 查询正文处理或扫描任务、当前页和候选进度 |
| `POST /{id}/process-structure`，正文 `{"resume":true}` | 显式继续高精度扫描；`false` 重新扫描 |
| `GET /structure-jobs/{job}` | 查询显式扫描任务 |
| `POST /{id}/confirm-structure-formula` | 人工核对后确认公式；`pendingScan:true` 只保存候选，最后一个公式确认也不会自动发布；`false` 修改已发布结果；同时校验来源版本、块 ID 和原候选 LaTeX，可携带 `artifactRevision` 防止核对时扫描已变化 |
| `POST /{id}/publish-scan` | 单独审核入库，提交当前候选的 `sourceRevision` 和 `artifactRevision`；重新验证完整性、待核对公式及旧可靠证据，成功后发布合格正文，并通知既有后台维护流程更新索引 |
| `POST /{id}/process-media`，正文 `{"force":false}` | 处理或重试已保留的公式与图片；`force:true` 强制重新请求视觉识别。可选 `localScan:true` 启动或继续 Office 嵌入图片的本地高精度扫描，并沿用每批续跑与同版本本地缓存；与 `force:false` 组合不会强制重新请求外部图片模型。省略 `localScan` 保持原行为 |
| `GET /media-jobs/{job}` | 查询单份媒体任务 |
| `POST /markdown-migrations`，正文 `{"force":false,"processMedia":true}` | 开始历史迁移；`processMedia=false` 修复结构、复用视觉缓存与图片，不发起新图片模型请求；原件解析仍可能执行本地 OCR |
| `GET /markdown-migrations/{job}` | 查询迁移结果、部分完成及索引结果 |
| `POST /{id}/source-locations`，正文 `{"text":"合成证据片段"}` | 将可靠正文映射到可用的原文位置 |

`force` 不会修改上传原件。图片资源接口要求当前 `sourceRevision`，只提供属于该版本资料的已验证 PNG 资产。Markdown 接口的 `selectedVersion` 表示实际选择，`artifactRevision` 绑定整份结果，`reviewSummary` 统计待核对内容，`retrievalReview` 给出是否可发布及阻塞原因。指定 `candidate` 而候选已变化/不存在时不会回退到已发布内容；携带的版本摘要不匹配时要求重新加载。
