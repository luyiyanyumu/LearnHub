# 智能体执行循环

LearnHub 将一次对话组织为“理解任务 → 更新计划 → 调用工具 → 检查结果 → 继续或收尾”。复杂任务可以在同一次请求中多次读取资料、修正方法、补齐工具并继续执行；简单问答不要求先列计划。执行状态来自实际调用与结果，不根据等待时间推算百分比。

## 计划与执行记录

`update_plan` 更新当前请求的完整计划，最多 6 步，每步包含 `step` 与 `status`。状态为 `pending`、`in_progress`、`completed`，最多一个步骤同时进行；空说明、重复步骤与未知字段会被拒绝。

过程面板分开显示“工作计划”和“实际执行”。计划经 `progress` 事件发送，`kind: "plan"`，稳定的 `plan-1` 等 ID 原位更新。界面把 `pending` 显示为“待执行”，把 `in_progress` 对应的进度状态 `running` 显示为“进行中”。缩短计划后，移除的旧项显示为 `cancelled` / “已调整”，保留调整记录。计划项不累计进实际执行步数，待执行也不等于待确认。

结束时未完成的计划仍保留待执行状态；工具报错、达到预算、等待确认均按实际结果显示。“本轮结果”记录停止原因。注册工具成功只是能力可用，智能体仍需实际调用它推进原任务，不能据此把整个任务标为完成。

## 循环边界

当前边界由 `AgentLoopState` 和 `AgentService` 统一执行：

| 边界 | 当前行为 |
| --- | --- |
| 模型循环 | 外层最多 16 轮；另可进行一次无工具收尾请求。历史摘要和工具内部的模型调用不计入这 16 轮，各自受相应预算约束。 |
| 工具预算 | 外层最多 40 次工具请求，每次模型返回最多处理 8 次；自适应工作流内部的原生工具与代码步骤另共用本请求 12 次调用预算。 |
| 时间预算 | 270 秒协作式预算：开始后续步骤前检查剩余时间；已经开始的外部工具仍受自身超时约束，因此不是到点立即中断所有操作的硬时限。 |
| 相同调用 | 工具名与规范化 JSON 参数构成签名；普通相同调用最多实际执行两次。已成功的写操作、已生成的待确认操作返回本轮缓存结果，避免重复提交。 |
| 没有进展 | 连续 3 轮没有新的成功工具结果时停止；仅更新计划不算取得进展。 |
| 完成检查 | 有未完成计划或新工具尚未使用时，最多提醒模型两次继续核对；等待确认时不靠继续循环执行写入。 |
| 明确收尾 | 区分回答完成、等待确认、时间/轮数/工具预算、停滞、上下文过大、模型错误、输出截断和未完成。 |

这些是单次请求的边界。当前工具按顺序调用，没有自动跨请求继续工作的后台目标调度器。浏览器切换会话或断开进度连接只停止前端接收，后台可能仍在完成并保存结果；因此前端不因断线自动重发整轮请求，也不把断线称为已取消后端工作。

模型连接异常最多在循环中恢复一次，已执行的工具结果随请求保留；模型引擎恢复请求也只能使用原请求的剩余时间。长文的大纲、分节及截断重写共用时间预算，耗尽后将实际生成的正文保留为待确认的未完成草稿，并列出尚未完成的章节。没有正文时不生成空白确认卡片。

## 上下文与结果

较早对话沿用持久化的“前情提要”；摘要调用失败或输出截断时退回原文摘录并保留已有提要。当前请求的工具结果另做大小控制：超过软边界时，仅节选较早的大结果，保留工具调用与返回的配对关系，以及最近两组调用所需的原文和内容哈希。节选明确标识正文不完整，精确引用或编辑必须重新读取原文；仍超过硬边界则停止并说明范围过大。

计划、执行记录和最终回答用途不同。计划表达准备做什么；工具记录表达实际发生了什么；最终回答应以已有证据、待确认操作与剩余事项为依据。生成工具仍遵守[自适应工具审查、测试与版本管理](agent-tool-evolution.md)，笔记修改仍保留确认、草稿和正文版本校验。

## 参考机制与取舍

本次参考 DSH `0.2.0-rc.2` 发布包中可见的实现与说明，没有复刻其完整运行时：

| 参考模块 | 观察到的机制 | LearnHub 的取舍 |
| --- | --- | --- |
| `dsh-agent-loop` | 独立的轮次与步骤边界；工具调用、结果和结束原因可回放；并行安全工具使用有界池，独占工具形成屏障。 | 保留步骤和结果记录；当前继续串行调度，避免并行写操作影响笔记状态。 |
| `dsh-tool-todo` | 会话拥有结构化计划，整体替换并验证条目；计划与工具执行是独立事件。 | 提供请求内计划与独立展示；计划完成不是执行成功的证据。 |
| `dsh-compaction-basic` | 压缩不拆开工具调用/返回，重试要求上下文确实发生缩减。 | 在原有历史摘要之外压缩较早工具结果，保留最近调用与版本信息。 |
| `dsh-llm-retry`、`dsh-repeat-tool-reminder` | 模型请求重试有分类和退避；重复工具调用可以触发换方法提醒。 | 工具重复和无进展有硬边界，不引入无限重试，也不自动重试结果不确定的整轮操作。 |
| `dsh-goal-round-driver` | 空闲、目标有效且有剩余轮次时才续行，并用版本边界拒绝过期任务。 | 作为后续跨请求调度的参考；当前未实现后台持续目标。 |

OpenAI 官方将 harness 描述为模型外层的上下文、工具、进度、失败处理与审批执行系统，产品仍负责自己的数据和业务规则。LearnHub 借鉴这种职责划分，继续使用现有后端与工具体系。[Codex as a platform](https://developers.openai.com/blog/codex-as-a-platform)

Codex Goals 的可借鉴点是明确结果、证据、预算和停止条件：仅在安全的空闲边界续行，并以实际证据判断完成；达到预算不等于目标完成。这是设计参考，LearnHub 当前没有接入 Codex Goals 或 app-server。[Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)
