# 原文阅读与划词翻译

资料库点击「阅读」，默认打开上传文件的「原文」。支持：

| 文件 | 原文阅读方式 |
| --- | --- |
| PDF | pdf.js 保留页面、图片、公式和文字层，支持页码、目录、缩放和连续阅读 |
| Word：docx / docm / doc | 从原文件生成可选中文字的阅读视图，保留标题、段落、文字样式、表格和内嵌图片 |
| Markdown：md / markdown | 读取上传的 UTF-8 源码，渲染标题、列表、代码、表格和数学公式 |

Word 以阅读顺序流式排版，分页、分栏、浮动对象及复杂公式的位置可能与 Word 软件不同；脚注、尾注、批注和页眉页脚集中展示。无法完整呈现的对象会给出说明，可以下载原文件核对。旧版 `.doc` 的复杂公式和批注有额外限制。

Markdown 图片只显示内嵌的安全光栅图片。外部图片及本地路径显示占位说明，不会自动访问外部地址；代码、链接、HTML 及公式经过安全过滤。

## 翻译交互

参考 [知云文献翻译](https://www.zhiyunwenxian.cn/) 的划选、修改原文后翻译和锁定译文交互：

1. 在左侧原文选择单词、句子或段落，选区显示黄色背景，右侧自动展示原文与译文。切到译文栏后仍保留当前待译文字的标记；重新划词会替换标记，清空、修改待译原文、切换文件或 PDF 重绘时移除。
2. 可关闭「划词自动翻译」，选完后手动点击「翻译」。
3. 在右侧原文框修正 PDF 选字错误，再重新翻译；这只修改待译文字，不改上传文件。
4. 勾选「锁定译文」后，新选区不会覆盖当前结果；解锁后继续选词。
5. 可切换简体中文、English、日本語、한국어，复制原文/译文、拖动调整侧栏或收起侧栏。窄屏自动改为上下对照。

「抽取正文」页的段落「译」按钮也使用同一套右侧译文栏。原文和译文分别滚动，工具栏文字不会混入选区。切换文件、语言或选区时，旧请求不会覆盖新结果；同一阅读会话缓存近期译文，点击「重新翻译」会重新请求模型。

翻译沿用「模型参数 → 阅读器翻译」的模型档案，单次最多 4000 个 UTF-16 字符。超长选择会明确提示缩小选区，不会截取前半段；模型返回截断内容也会报错。实际调用使用现有配置的模型，原文预览本身在本地解析，不调用模型或云端文档转换。

## 抽取正文的 LaTeX 公式

「抽取正文」支持公式渲染、复制 LaTeX、查看源码和手动修正。修正仅作用于当前阅读预览及「复制正文」，不会改动上传文件；关闭阅读器后恢复自动还原结果。

- Word（docx/docm）读取原生 OMML 公式结构，转换分式、根号、上下标、上下限和矩阵等结构。表格、标题、脚注中的内联公式也可显示。旧版 `.doc` 的嵌入公式仍需查看原文件。
- PDF 根据字符位置和绘制的数学结构生成 LaTeX。不可靠的几何结果默认折叠，优先显示原图；点击「识别公式」可让图片模型直接读取 300 DPI 公式截图，保留上下标、多行结构、花体和式号。识别结果仍须对照原图核对。
- Markdown 保留原有 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 数学表达式，代码与货币符号不会被当作公式。

「复制正文」将公式输出为 `$$...$$` 源码，使用识别后的结果或当前视图的手动修正。公式渲染在本地进行；只有主动点击识别按钮时，才将单个公式截图发送至「模型参数 → 公式原图识别」指定的模型。该任务默认使用当前激活档案，需支持图片输入；当前 DeepSeek Flash 可直接使用，普通文本模型会提示换档案。不会自动逐页发送整份资料。

模型识别候选保存在 `uploads/.derived/<资料ID>/formula-ocr/`，前端验证可渲染后才确认保存为正文结果，重新打开同一原文件可复用；点击「重新识别」跳过缓存。缓存按源文件内容、区域、模型和识别提示词版本隔离；模型调用失败、截断或无法渲染的候选不会替换已有确认结果。确认保存失败时，预览保留并提示仅本次阅读有效。手动修正仍只作用于本次阅读，历史检索正文不会因此自动重写。扫描页缺少文字时，目前仍需从原文阅读，尚未提供整页扫描件的公式检测。

`GET /api/files/{id}/text-layout` 的公式块保留 `text`、`page`、`rect`，另含 `latex`、`latexStatus`（`restored` / `partial` / `unavailable` / `recognized`）和 `latexMessage`。`recognized` 表示来自图片模型，仍须核对。Word、Markdown 按结构顺序显示为逻辑阅读页，不代表原文件的精确分页。

`GET /api/files/formula-recognition/capabilities` 返回识别任务的模型与配置状态。`POST /api/files/{id}/formula-recognition` 接受 `{page,x0,y0,x1,y1,force}`，只从原 PDF 裁图；返回 `{latex,status,message,profile,model,cached,ms,cacheKey}`。前端校验 LaTeX 可渲染后，调用 `POST /api/files/{id}/formula-recognition/accept`，提交 `{page,x0,y0,x1,y1,cacheKey}` 确认该候选。候选凭据绑定文件内容、区域和结果，原文件变化会使确认失效。相同任务合并在途请求，同时最多识别两个不同公式；模型调用超时 120 秒，不阻塞等待中的 HTTP 线程。不会执行图片里的指令。

## 接口

`GET /api/files/{id}/original-preview` 返回：

```json
{
  "id": 12,
  "originName": "example.docx",
  "ext": "docx",
  "format": "word",
  "html": "<div class=\"word-document\">...</div>",
  "source": "",
  "warnings": []
}
```

Markdown 的 `format` 为 `markdown`，原始内容在 `source` 字段。Word 使用安全生成的 `html`，前端再过滤后渲染。超过文件、解压、图片或输出限制会给出说明，无法完整预览时仍可下载原文件。

翻译复用 `POST /api/files/{id}/translate`，请求体为 `{text, targetLang}`；`GET /api/files/translate/capabilities` 提供语言、长度上限和当前模型信息。
