# 笔记定向编辑工具

在笔记页打开智能体，可以直接说：

- “给当前笔记添加目录，只显示二级到三级标题。”
- “删掉第 2 处‘其实’，其他文字保留。”
- “把‘这是我的知识笔记’里的‘的’删除。”
- “把 Python 中的 t 加粗，并把‘重点’设为红色。”
- “在‘注意事项’前插入一段说明。”

智能体先用 `get_note` 读取正文和 `content_hash`，再调用 `edit_note`。所有局部改动合成一次调用，卡片显示每项改动前后的片段，确认后写入并同步当前编辑器。发送当前笔记上下文、确认笔记写操作、融入或光标插入前，编辑器会自动保存当前草稿，不再要求逐次手动保存。保存失败、输入法尚未结束、切换笔记或版本冲突时停止后续修改并保留草稿；后台标签页不会被保存为当前笔记。

同一文本有多个匹配时必须指定第几处或前后文，工具不会自动选第一处。自动保存不跳过写入预览或正文版本校验；生成预览后又修改正文，需基于最新版本重新生成预览。

## 多处补写与分批融入

需要生成较长内容、多章节补写或分散插入多个位置时，先读取笔记，再用 `write_note_sections` 提交完整目标：`note_id`、`expected_hash` 和 `tasks`。每项任务包含 `action`（`insert_before`、`insert_after` 或 `replace`）、精确原文 `text`、可选定位字段、`heading` 和 `instructions`。简单精确改字、删字和格式操作仍使用 `edit_note`。

服务端必经独立只读规划器，将本轮原始请求、相关历史、当前正文版本和完整大纲作为范围依据，生成并冻结最多 50 项分工。主智能体传入的 `tasks` 是规划线索，服务端会据此规划完整任务，不能只提交前三节后就要求用户确认下一批。历史回复中列出的“后续批次”不会自动成为用户要求每批暂停的新任务；用户明确限定“只处理本批”或指定小节时，按该范围处理。

分工在服务端内部以最多 3 个只读子智能体并发调度，前一项完成后继续处理后续项，全部片段完整并校验版本后才合成一张 `edit_note` 确认卡片。任一片段失败、截断、公式或代码围栏未闭合，或预算不足，整批不提交部分审批、不写入笔记。独立规划和冻结清单有助于检查遗漏，但规划仍取决于模型对用户范围的理解，并不证明语义覆盖绝对完整。

生成片段由程序补足段落边界，不依赖模型自行返回首尾空行。定位到标题文字时，插入点会移到完整标题前后，保留 ATX 标记和 Setext 下划线；同一位置的多个片段按计划顺序分段连接。AI 光标插入遇到标题时也会保留完整标题，将正文放到其后；普通单字插入和明确选区替换仍按精确位置处理。

长笔记的“融入”会一次定位多个目标小节，最多 3 项同时生成，在原文快照上组装全部补丁后统一预览。新章节可放在指定章节后，未涉及的小节保留原文；批量应用和光标插入可撤销。预览应用前也会自动保存已有草稿，应用后的新改动仍显示未保存，方便核对后继续编辑。

## 按任务显示操作选项

模型通过 `set_reply_actions` 或最终回复中的结构化 `replyActions` 给出最多 4 个相关操作，支持继续追问、另存笔记、融入当前笔记和光标插入，界面始终保留复制。建议及目标笔记绑定本轮任务，刷新历史会话后仍可恢复；旧会话没有建议时只显示复制。

动作使用受限的 `kind`、`label` 和追问 `prompt`，不执行模型输出的脚本、任意地址或原始工具参数。生成内容达到输出上限时，不提供将不完整答案写入笔记的操作。

## 参数示例

```json
{
  "note_id": 12,
  "expected_hash": "从 get_note 返回的 content_hash 原样复制",
  "operations": [
    { "action": "delete", "text": "其实", "occurrence": 2 },
    { "action": "format", "text": "t", "prefix": "Py", "suffix": "hon", "style": "bold" },
    { "action": "insert_toc", "min_level": 2, "max_level": 3 }
  ]
}
```

支持 `replace`、`delete`、`insert_before`、`insert_after`、`format`、`insert_toc`。用 `occurrence`（从 1 开始）选择某处，或用紧邻的 `prefix` / `suffix` 定位。只有明确要修改所有匹配时才传 `all: true`。操作依次作用于上一步结果，后续操作的定位文本也要按修改后的原文填写。

`format` 支持加粗、斜体、下划线、删除线、行内代码、文字颜色、背景色、字号、上标和下标。文字颜色/背景色的 `value` 使用 `#RGB`、`#RRGGBB` 或 `red` 等英文颜色名；字号使用 `8`～`72` 的整数文本（px）。格式目标只接受行内正文文字，代码块、链接地址、HTML 属性和 Markdown 结构不能作为格式目标。已有 HTML 正文里的单个字也可以定位；原有文字和非目标内容保留。

目录默认位于正文开头，也可用 `placement: end` 放到末尾，或用 `before` / `after` 和 `text` 定位。目录采用与预览、HTML 导出一致的标题锚点，支持同名标题、Setext 标题，忽略代码块和 HTML 注释中的伪标题。工具生成的目录带隐藏标记，再次调用会更新它；手写目录不会自动覆盖。

## 接口与 MCP

- `GET /api/notes/{id}`：详情带 `contentHash`。
- `POST /api/notes/{id}/edit/preview`：请求只传 `expected_hash`、`operations`；返回改动片段，不写入。
- `POST /api/notes/{id}/edit`：确认后执行同样的操作与版本。正文变化时拒绝写入，任一操作失败时整批不写入。
- MCP `get_note` 返回 `content_hash`；`edit_note` 采用同一套参数，并增加 `dry_run`，默认 `true` 只预览，检查后传 `false` 执行。

一次最多 50 项操作。返回 `beforeHash`、`afterHash`、`changed` 和每项的命中数量/前后片段；长片段会明确标记截取。写入只更新正文、摘要和更新时间，并沿用学习记录与 Wiki 的内容变更通知；标题、分类、标签保持原样。
