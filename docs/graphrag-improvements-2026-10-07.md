# 知识图谱与 GraphRAG 改进

知识库图谱改成画布与详情分栏，支持概念/别名搜索、社区筛选、关系筛选、1～2 跳邻域、孤立概念开关。默认仅显示模型抽取关系；规则推导可单独显示，详情与画布使用相同筛选范围。关系卡展示方向、证据和原文入口，缺少证据的抽取关系标为待核对。

布局按社区和连通分量确定性初始化，节点位置不再被夹到画布边界。缩放时标签保持可读字号并避让，密集节点使用引线标签。搜索后的邻域适应整个画布，放大/缩小与适应视图放在左下，避开智能体悬浮入口。

邻域使用以查询概念为中心、按跳数分层的稳定环形布局。进入邻域时丢弃全图遗留坐标和速度，避免社区锚点与连线把局部节点拉成窄带；选中另一个节点查看详情不改变布局中心。相同数据刷新保留手动位置，切换中心或关系范围重新排布，缩放只改变视角。邻域无需持续运行力学模拟，适应视图使用独立于当前缩放的节点半径。

## 检索行为

- 页面融合检索、智能体自动检索、`search_knowledge` 工具及检索评测共用 `KnowledgeRetrievalService`。关键词匹配当前正文、向量召回语义相近片段、图谱召回关系对应的原文片段，按片段进行 RRF 融合，再统一重排。同一来源不同段落分别保留，每条结果报告实际参与的召回通道。
- 图谱检索识别问题中的实体，优先连接多个问题实体的直接关系。只有具有明确来源、完整证据能在当前正文中找到的模型抽取关系才进入融合；规则推导、证据缺失、原文已删除或证据已失效的关系不参与。跨段证据保留原文窗口，不强行挂到单个不完整段落。
- 向量结果与当前正文的段落编号及内容核对，避免正文修改后旧向量引用错误段落。某路失败时保留其他路结果；仅三路都没有结果时才尝试查询改写。关键词、向量评测模式保持独立，不混入图谱或重排。
- 候选池与最终结果为其他来源保留位置，避免长笔记的多个片段占满结果。融合候选最多 20 条，在同一批完成列表重排，避免旧分批交错逻辑提前展示低位候选。已核验的图谱关系置于重排摘要前部，防止 120 字摘要截断关键关系。重排返回不完整顺序时保留遗漏候选，不静默丢失证据。
- 英文名匹配保留词边界，避免 `Planning` 误命中 `ANN`、`JavaScript` 误命中 `Java`。长名称消费自身匹配区间，括号内明确出现的概念也能被识别。
- 整库主题问题使用有效社区摘要。有明确主题或概念种子时，按相关性选择摘要，限制材料数量与字符预算。
- 智能体和回答评测共用 `RetrievalContextService`，总检索材料预算 7000 字符。按实际存在的 Wiki 和全局摘要预留额度，缺失时退还给正文。局部图谱只通过核验后的正文片段进入上下文，不再额外拼接未经当前正文核验的关系块；全局摘要只读有效缓存。含图谱关系的片段整段注入或跳过，引用列表只展示实际注入的材料。
- 检索页显示“关键词 / 语义 / 图谱”、段落位置和命中关系。融合分表示 RRF 排序分，不作为相似度百分比；智能体引用显示对应通道及关系，便于核对图谱是否参与。结果摘要在截断前清理 HTML 排版标签并解码常见实体，保留表格单元格边界、Java 泛型和代码符号；清理仅处理字符串，展示时仍统一转义。来源使用 `passageKey` 区分不同证据窗口，负数段落编号显示“证据片段”。
- 独立的 GraphRAG 检索验证入口仍可检查局部路径、全局摘要与路由原因。该验证接口默认不生成摘要或调用综合模型，显式 `synthesize=true` 才综合；统一融合检索会按现有设置调用向量模型和重排模型。

这属于项目现有图谱上的轻量检索实现。设计参考 [Microsoft GraphRAG 查询文档](https://microsoft.github.io/graphrag/query/overview/) 的局部/全局区分，不等同于完整的 Microsoft GraphRAG map-reduce 或 DRIFT。

## 社区与摘要缓存

划分指纹包括节点、加权边、分辨率和随机种子，存于内部设置项；纯删除和同秒变更也会触发重算。社区归属与指纹事务提交，普通 GET 不隐式重算。

摘要输入指纹包括成员信息、关系证据、来源正文指纹和模型身份。正文证据必须在当前来源中全文匹配；仅有简介、推导关系或已删除来源不能支撑摘要。生成期间材料再次变化，结果不作为当前摘要保存。来源正文只在服务内部核验，不通过摘要接口返回。

社区编号变化时，可按输入指纹复用摘要并重新关联。过期、孤儿或没有原文支撑的摘要不能进入全局检索。首次升级后，旧指纹的摘要需要重新生成。

在“检索验证 → 社区摘要”中主动生成/更新，每次最多 3 次模型调用，失败也占调用预算；图谱划分过期时先本地重算。关系仍来自上次抽取，修改正文后应重建图谱以更新关系本身。

## 续接改进：实际读取的依据与原文入口

智能体使用 `search_knowledge`、`get_note`、`get_quick_ref`、`get_file` 后，成功返回的正文和查询片段会加入本轮核验材料，并在引用中标明“工具读取”。资料按实际返回的全文、说明或查询片段收集，不从数据库额外补入模型没有看到的正文；不同片段保留独立证据窗口与偏移。相同正文重复读取不重复计入预算，关键词、向量和图谱来源信息合并保留。未保存的编辑器节选参与核验，但不冒充已落库的原文引用。

核验材料超过 7000 字符或回答超过 3000 字符时，直接报告“未完整核验”，不对截断后的材料或回答发出完整通过结论。成功读取尚未纳入原文核验的图谱、网页等工具材料，也明确报告核验范围不完整。核验 JSON 缺少必要字段、类型错误、有尾随内容，或调用失败时保留正常回答并报告未核验。前端尊重 `checked=false`，兼容旧响应，矛盾或格式不完整的响应不会显示“依据已核对”；关闭核验时不展示核验状态。

检索结果与智能体来源可直接打开对应笔记、速查卡或资料原文。资料和速查卡的 `read=id` 在同一页面变化时也会更新阅读内容，不受当前分页和分类筛选影响；慢旧请求、关闭阅读器或卸载页面后的请求不会覆盖当前内容。检索页按发起时的问题和方式发布最新结果，过期请求的结果或错误不会覆盖新查询，也不会弹出过期的失败提示。

整库路由补充“全部知识的总体主题”等明确范围表达，并去除总体问法的范围噪声，避免路由到全局后因残留“全部总体”匹配不到任何摘要。具体关系、区别和如何类问题保持局部检索；单独的“全部”或“总体”不触发全局。“知识产权”“知识工程”等技术术语不被截成整库范围，明确的 ReAct 主题词仍用于筛选相关社区。
