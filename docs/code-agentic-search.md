# 代码区智能检索

代码区默认使用 Agentic Search。输入实现意图，例如合成问题“哪些代码在连接失败后执行重试？”，模型可以搜索符号、关键词和文件，再读取有行号的代码窗口，根据工具返回内容继续调整查询，最后归纳结果。符号、关键词和原有组合模式仍可直接使用；空输入只列出代码，不调用模型。

## 检索范围与依据

项目内检索绑定当前项目，“未归类”绑定没有项目的片段，首页检索覆盖整个代码区；语言筛选在每次搜索和原文读取时生效。模型不能通过工具参数改变这些范围。底层数据库查询在候选上限之前应用范围。

结果展示模型归纳、实际工具步骤、命中片段和已读取的代码依据。依据的行号与原文由服务器核对，最终结果只能引用当前范围中实际发现并读取的片段。代码内容作为待分析材料，不能扩大工具权限；工具只支持查询与读取，不执行代码、命令、联网或写入。

“读取依据”表示原文窗口真实存在，不等同于模型归纳中的每项解释都已通过独立事实核验。没有可靠依据时，界面明确展示检索受限或普通候选。模型不可用时退回范围内的普通检索；轮次、工具调用、时间和代码读取量都有上限。

每次最多 6 轮模型调用、12 次工具调用，累计读取最多 18,000 字符；单个代码窗口最多 80 行和 4,000 字符，并保持完整行。探索阶段使用 90 秒时间预算，单次模型请求另有限时；数据库查询和最终原文复核可能增加总耗时。达到限制时保留仍能核对的已读代码，并明确标记检索未完整完成。

搜索方式、问题、语言或项目变化时，页面取消旧请求，并用请求代次阻止旧结果或旧错误覆盖当前状态。原文详情独立管理请求，可从证据入口跳转到对应代码行。

服务器在收尾时重新读取并核对对应完整行；打开详情时页面再次比较依据与最新原文。原文变化后停止旧范围高亮，并提示重新检索。

## 接口

`POST /api/code/agentic-search`，请求示例仅使用合成标识：

```json
{
  "question": "连接失败后在哪里重试？",
  "repoId": 101,
  "lang": "java",
  "limit": 8
}
```

`repoId` 和 `lang` 可省略；`unassigned: true` 表示仅搜索未归类片段。响应沿用项目的 `Result` 包装，`data` 含 `answer`、`status`、`model`、`rounds`、`steps`、`results`。状态为 `completed`、`limited` 或 `fallback`；片段结果含 `reason` 与 `evidence`，每条依据含 `startLine`、`endLine`、`quote`。

模型使用现有模型档案，任务为“代码智能检索”（`code_search`），可在模型分工中选择档案。检索没有接入代码向量表或概念 GraphRAG；模型通过多轮底层搜索与读取来寻找代码。

## 验证方式

后端测试使用模拟模型、合成代码和 mock 数据访问，覆盖查询改写、代码读取、范围限制、虚构来源、读取预算、重复工具调用和模型失败。前端测试覆盖请求取消与乱序、状态展示、证据范围和原文入口；浏览器核验使用隔离的合成 API，不访问本机代码库、数据库或真实模型。
