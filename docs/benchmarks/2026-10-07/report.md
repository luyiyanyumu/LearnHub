# LearnHub：当前融合检索与仅向量检索实测

2026-10-07，使用当时运行的 LearnHub，按同一批问题、同一知识库、前 5 个片段进行比较。**本轮可复核题集没有测出来源命中率的净提升，主要改善是把预期来源排到首位。**本轮评估检索来源与排序，没有测量生成答案准确率。

本报告仅公开聚合指标、实验协议和方法限制。原始问题与答案、语料文本、标注与逐题结果、原始调用日志及数据库历史快照保留在本地，不随仓库提交或发布。公开报告不包含原始导出文件的下载链接，也不能单独用于复核逐题判分。

原始 99 题都实际运行了，随后保留原始结果，并对标注来源的当前正文进行复核。66 题的来源内容可以支持题意；16 题全部标注来源已删除；8 题标注正文不支持问题；9 题存在指代或内容深度歧义。实验期间原题、标签、业务代码和应用设置均未修改。统一按正文规则判定，仅将 supported 题计入下列 66 题主指标，未按哪组得分高低挑选题目。

原始标签下新增来源命中 4 题、丢失 2 题，但正文复核发现部分标签不能支持题意，新增来源命中不能据此证明检索找到了答案。上表原始标签结果保留用于说明统计口径差异，主结论以正文复核可用题为准。

另有 2 题明确要求同时召回两条必要来源，其他多标签多数表示备选来源。向量对这 2 题都召回了两条来源，融合仅 1 题召回齐全。其中 1 题有指代歧义，已从 66 题主指标排除。这是小样本诊断，不能估计普遍的跨资料准确率。

实验协议：

- 使用 `POST /api/kb/eval/run`，先运行 `vector` 基线，再运行 `fused`；两组使用同一题集、同一知识库和 `topKPassages=5`。
- 知识库有 22 个来源、2,105 个向量片段；嵌入模型为 `bge-m3`，索引未过期。题集、索引规模、来源最后修改时间、索引时间和重排设置在两组前后相同。
- 融合使用词面、向量、经过原文核验的图谱候选、RRF 和模型重排；每通道候选上限为 24，融合重排窗口为 20，重排后端为 `llm`，模型为 `deepseek-flash`，温度为 0.1。
- 向量基线在北京时间 20:42:20—20:42:59 完成，整轮用时 39.5 秒；融合在 20:43:24—20:45:53 完成，整轮用时 149.6 秒。融合评测同时另外执行每题词面和向量对照，因此 149.6 秒不能直接当作纯融合检索耗时。

日志核验显示 99 次融合调用、99 次词面调用和 99 次向量对照调用；其中 49 题召回了图谱候选，未出现明确的召回或重排失败日志。融合运行中的向量对照与独立向量基线均为 77/99。图谱在本轮参与了候选召回，但词面与重排也一并改变，不能把整体排序收益全部归因于图谱。

接口中的 `recallAtK` 实际是任一标签来源命中率：先取 K 个片段，再将来源去重。MRR 也是去重后的来源位次，不能误写为片段 MRR。命中一篇长笔记，并不证明返回片段包含所需事实。本轮没有生成并核验问答，也没有评估拒答、引用正确性、wiki 注入或全局社区摘要。34 个社区摘要当时均新鲜，但检索级评测接口没有运行全局摘要上下文。

复算需要使用者自行提供本地保存、且有权使用的完整运行导出；公开仓库不提供这些问题、正文或历史快照。分析脚本要求导出目录中包含前后题集与状态、两组逐题运行结果、对照响应、来源检查、人工复核及融合检索日志。可在仓库根目录执行，并将示例路径替换为实际本地目录：

```bash
node tools/analyze-retrieval-benchmark.mjs /path/to/local/benchmark-exports
```

脚本会验证两组问题逐条相同、标签相同、语料与设置未变、向量对照一致、来源位次正确，以及重算结果和后端原始汇总一致；不会再次调用模型或修改数据库。它会在所提供的本地导出目录中生成配对比较结果，因此该目录也应保留在本地，勿将原始导出或生成的逐题比较结果提交到公开仓库。
