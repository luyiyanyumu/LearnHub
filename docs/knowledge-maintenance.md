# 知识库后台自动维护

自动维护默认开启，后端启动后先检查已有资料，随后约每 10 秒检查一次原文与配置；连续保存会合并处理。知识库的内容变更与模型、切块配置变更由后端合并调度维护。知识库页面的“知识库维护”抽屉顶部提供总开关、当前阶段、各步骤的实际状态、上次运行时间与错误；关闭抽屉或离开页面不会中止已经进入后台的工作。

源码 Docker 部署需要先把新代码构建到前后端镜像，再更新运行容器。仅修改源码、在宿主机打包或重启旧容器，仍会运行原镜像。在当前实例的 `deploy` 目录沿用已有 Compose 配置执行 `docker compose build backend frontend`，成功后执行 `docker compose up -d --no-deps backend frontend`，最后刷新浏览器。数据库和上传资料继续使用原有数据卷。新版面板顶部应出现“后台自动维护”；`GET /api/knowledge/maintenance` 应返回维护状态。

开启自动维护后，后台按需处理向量索引、Wiki、图谱、文档关联、社区、摘要和自检。未配置的模型、尚未完成的批次、失败与跳过均以服务端消息说明；“已排队”仅代表待处理，某一阶段完成也不代表全部知识结构已经更新。

阶段进度与开关持久保存，重启后继续；失败按 30 秒到 10 分钟退避重试。没有来源或相关配置变化时，不重复调用模型。概念图谱按来源分批续作，全文抽取会保留多行公式；自动维护保留已有知识页、手工实体与关系，不自动合并实体。文档关联沿用最多 40 条候选的有界生成策略，实体编译每轮最多选出 10 个主题页，状态完成表示当前策略下的维护已完成。

历史实体页缺少相关的当前原文时，自动维护保留原页及其待更新标记，并在阶段说明中显示保留数量；来源变化后重新检查，不反复生成空页。普通页面或图谱来源失败时，会轮换处理其它待办。长来源的图谱抽取每轮每来源最多处理 3 批，已成功的批次持久暂存，全部完成并核验来源未变后才替换旧关系；重启或失败后从未完成批次继续。普通分片目标 4000 字符，完整公式和代码块可独立到 32000 字符，超过上限保留旧图并明确说明，不拆开多行公式。

各阶段会返回具体的业务原因及重试时间；“重试维护”可立即重新排队失败步骤，已完成步骤无需重做。某阶段恢复后会清除它的旧错误，保留仍未恢复的其它阶段错误。

模型服务的 TLS 握手、连接失败、地址解析失败和超时会显示对应中文原因，保留已完成进度，并按退避计划自动重试。网络恢复后继续处理；状态和错误摘要不展示密钥或服务原始错误响应。

图谱实体的归一化名称使用精确的字符比较，与程序生成实体 ID 的规则保持一致。字形相近但编码不同的名称不会因数据库的模糊排序发生唯一键冲突，也不会自动合并；数据库约束、字段长度或写入锁失败会显示脱敏后的具体类别。

“立即维护”与“重试维护”只向后端排队，不由浏览器逐项调用重建接口。页面轮询只读取状态，卸载后取消读取和定时器；重新进入页面继续读取后台当前状态。关闭总开关后，可再次开启或按需点击立即维护。

保留的“分类与标签 Wiki 自动更新”开关只控制这两类主题页，“自动维护索引”开关控制向量索引及图谱实体向量是否参与自动维护；配置有效的嵌入模型后，实体向量在 Wiki 与概念图谱更新完成后同步。总调度归后台自动维护服务；关闭其中一个专用开关，不表示其他维护步骤也已关闭。

常用流程不需要依次点击全部重建按钮。原有单项重建、图谱修复、社区计算、自检与检索体检保留在高级修复区域，用于排查特定问题。模型和知识库参数保存后，设置界面展示后端返回的待更新状态；总开关关闭或状态无法读取时，不会承诺自动更新已经发生。

接口均使用 `/api/knowledge/maintenance`：`GET` 读取状态，`PUT {"enabled":true}` 调整总开关，`POST /api/knowledge/maintenance/run` 排队执行。状态中的 `message`、`phaseLabel`、`steps` 与 `lastError` 是判断本次结果的依据，时间为空时显示“—”。例如合成资料“示例图书借阅流程”发生变更后，可先显示“已排队”，随后逐阶段显示实际进展；未执行的图谱步骤不会被标为成功。
